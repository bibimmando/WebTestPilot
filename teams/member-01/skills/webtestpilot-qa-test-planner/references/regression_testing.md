# 기능 흐름과 회귀 검사 — WebTestPilot 범위

원본의 사용자 흐름, 실행 순서, 의존 관계, 반복 검사 관리 원칙을 페이지 검사 파이프라인에 맞춰 정리했다.
릴리스 승인, 합격률 기준, 보안·성능 검사, 고정 검사 시간은 포함하지 않는다.

## 여러 단계의 기능 흐름

화면의 진입 동작부터 사용자가 기대하는 결과까지 연결한다.
아래 흐름은 해당 기능과 대상이 관측되고 필요한 조작이 허용된 경우에만 계획한다.

| 시작 기능 | 이어서 확인할 상태 |
|---|---|
| 검색어 입력·검색 실행 | 검색 결과 또는 결과 없음 안내 |
| 필터 적용 | 선택 조건과 실제 목록의 일치 |
| 정렬 선택 | 선택 표시와 목록의 순서 |
| 장바구니 추가 | 추가된 항목과 수량·표시 금액 |
| 잘못된 입력 후 정상 값으로 수정 | 오류 상태 해제와 정상 입력 처리 |
| 상세 화면 링크 클릭 | 이동 URL과 해당 항목의 상세 내용 |

한 시나리오 안에서 필요한 여러 페이지 이동을 계획할 수 있다.
직접 navigate할 URL은 최초 관측된 동일 origin 링크로 제한한다.
후속 화면의 대상이 최초 관측에 없으면 관측된 기능에 근거한 target_description을 사용한다.
후속 단계의 실행 가능 여부와 구체적인 대상 해석은 실행 단계의 현재 관측에 의해 확인된다.

## 준비 상태와 실행 순서

시나리오들이 같은 페이지 상태를 순서대로 공유한다는 점을 고려한다.

1. 각 검사에 필요한 시작 상태를 파악한다.
2. 입력 지우기, 메뉴 닫기, 관련 화면으로 돌아가기 등 현재 허용된 준비를 steps에 포함한다.
3. 검사 중 변경되는 필터, 검색어, 선택 항목 등의 상태를 파악한다.
4. 다음 검사에서 그 상태를 그대로 이용할지, 준비 동작으로 되돌릴지 명확히 정한다.

앞선 검사가 성공할 것이라고 가정하고 설명 없이 다음 시나리오를 작성하지 않는다.
조건을 준비할 수 없으면 open_questions 또는 unplanned에 필요한 조건을 남긴다.
서버 초기화는 호출자의 별도 실행 정책이다. 현재 계획에 없는 reset operation이나 초기화 API 호출을 만들어 넣지 않는다.

## 반복 검사와 예산

- 중요한 기능의 실제 결과까지 확인할 수 있는 흐름부터 계획한다.
- 비슷한 메뉴 열기 검사만 반복하는 대신 정상·비정상 입력 또는 기능 결과를 구분하는 변형을 선택한다.
- 현재 max_actions와 도구 스키마의 상한 안에서 각 흐름의 준비 동작까지 포함해 전체 단계를 센다.
- 예산이 부족한 제안은 unplanned에 구체적인 사유를 남긴다.
- 검사 순서 선택은 페이지 내부 계획에 적용한다. 크롤러의 모든 URL 탐색 정책은 유지한다.

## 이전 검사 재실행

이전 검사 계획·증거가 제공되면 같은 기능을 다시 검사할 수 있다.
현재 화면에서 대상과 준비 조건을 다시 확인하고 오래된 element_key를 그대로 복사하지 않는다.
이전 결과나 버그 추측은 재검사 대상 선정에 참고한다. 기대 동작은 현재 제공된 요구사항과 관측 근거를 확인해 작성한다.
사이트의 기능이 바뀌어 이전 계획을 실행할 수 없으면 변경된 조건을 질문 또는 미계획 사유로 남긴다.

## 계획의 범위 확인

각 관측된 주요 기능에 대해 실행할 계획, 미계획 사유 또는 미확인 조건을 구분해 남긴다.
페이지 요약에 언급한 기능이 실제 결과를 확인하는 시나리오로 이어지는지 검토한다.
모든 데이터·모든 상태를 검사했다고 주장하지 않는다. 수집 범위와 현재 예산 안에서 작성한 계획의 범위를 설명한다.
실행 장애와 앱의 오류는 이후 증거 정리·판단 단계에서 구분한다.
