# 주입한 결함 목록 (F · V · U · N)

레지스트리 네 파일에 등록된 **10건**의 증상과 확인 방법을 한곳에 모았다.
레지스트리는 기계가 읽는 자리(정답지 생성)이고, 이 문서는 사람이 읽는
자리다. 증상 · 재현 절차 · 확인용 코드 조각은 여기에 둔다.

| 접두사 | 분야 | 건수 | 레지스트리 | 브랜치 |
|---|---|---|---|---|
| `F` | 기능적 | 4 | `server/bugs/functional.ts` | `feature/bugs-functional` |
| `V` | 입력 검증 | 2 | `server/bugs/validation.ts` | `feature/bugs-validation` |
| `U` | UI | 2 | `server/bugs/ui.ts` | `feature/bugs-ui` |
| `N` | 이동 · 라우팅 | 2 | `server/bugs/routing.ts` | `feature/bugs-routing` |

```sh
npm run dev                  # 정상 — 기준선
BUGS_ON=all npm run dev      # 10건 전부
BUG_F2=1 npm run dev         # 한 건만
```

```
GET  /api/bugs    지금 켜진 ID 목록
GET  /gt.json     정답지 (레지스트리에서 생성한다. 손으로 쓰지 않는다)
POST /_reset      시드 상태로 되돌린다. {"seed": 42} 로 게임 시드도 고정한다
```

**평가는 10건을 전부 켠 상태로 한다** (EC2 `54.180.42.43:8001` 과 같다.
정상본은 `:8000`). 아래 재현 절차는 정상본과 전부 켠 판을 같은 절차로 돌려
확인한 것이다. 한 결함만 보여줘야 할 때만 `BUG_U2=1` 처럼 한 건씩 켠다.

테스트 계정은 README 의 "테스트 계정" 과 같다 (비밀번호는 모두 같다).
두 계정을 동시에 써야 하면 하나는 일반 창, 하나는 시크릿 창으로 연다.

# 규칙으로 잡히는가 — 한눈에 보기

## 판정 기준

**규칙** — 그 화면의 정답을 코드에 적어 넣지 않고, 어느 사이트에나 통하는
결정적인 검사로 "이상하다" 는 신호를 낼 수 있으면 규칙으로 잡힌다. 예를 들면

- 링크가 404 · 엉뚱한 곳으로 넘어간다
- 링크 글자와 도착한 화면의 제목이 다르다
- 버튼을 눌렀는데 아무것도 바뀌지 않는다
- 뒤로 가기를 눌렀는데 직전 주소로 돌아가지 않는다
- 화면을 옮겼는데 스크롤이 맨 위가 아니다
- 글자 대비가 낮다, 가로로 넘친다, 잘렸는데 줄임표가 없다

어떤 검사 도구가 **지금** 그 검사를 갖고 있는지는 따지지 않는다. 결함의
성질만 본다.

**AI** — 아래 둘 중 하나면 AI 가 필요하다.

| 구분 | 뜻 |
|---|---|
| **필수** | 규칙이 낼 신호가 아예 없다. 화면이 정상으로 보이고, 이상하다는 걸 알려면 기대 동작을 알아야 한다 |
| **판정** | 규칙 신호는 나지만 같은 신호가 정상 상황에서도 실제로 난다. 둘을 가르려면 그 화면의 의도를 알아야 한다 |

## 10건 판정

10건 모두 **C. AI 필수** 다. 결함을 고를 때 위 규칙에 걸리는 것은 뺐다.
레지스트리에도 모두 `detectable: false` 로 적혀 있다.

| ID | 결함 | 규칙 | AI | 근거 |
|---|---|---|---|---|
| F1 | 탈퇴한 커뮤니티 글이 홈에 남음 | ✗ | **필수** | 홈 피드가 정상적으로 글을 보여 준다. 머리글의 가입 목록과 피드 글의 커뮤니티를 짝지어 봐야 안다 |
| F2 | 다른 계정의 최근 본 글 | ✗ | **필수** | 최근 본 글 목록이 정상 모양으로 뜬다. 지금 계정이 그 글을 본 적이 없다는 앞 단계의 기억이 있어야 안다 |
| F3 | 답글 알림을 꺼도 옴 | ✗ | **필수** | 알림이 오는 것 자체는 정상 동작이다. 설정 문구 "내 댓글에 답글" 과 알림 종류를 맞춰 봐야 안다 |
| F4 | 정지된 사용자가 답글은 씀 | ✗ | **필수** | 등록 성공은 정상 신호다. 정지 안내 "글과 댓글을 쓸 수 없어요" 에 답글이 포함된다는 걸 알아야 한다 |
| V1 | 하이픈 넣은 번호 거부 | ✗ | **필수** | 거부 메시지가 뜨는 건 정상 동작이다. 메시지의 예시가 방금 넣은 형식과 같다는 걸 읽어야 안다 |
| V2 | 한글 링크 주소 거부 | ✗ | **필수** | 거부 자체는 정상 동작이다. `https://` 로 시작하는 한글 주소가 올바른 주소라는 걸 알아야 한다 |
| U1 | 댓글 신고 창 제목이 "글 신고하기" | ✗ | **필수** | 창은 잘 열리고 제목도 있다. 댓글에서 열었다는 맥락과 제목을 맞춰 봐야 안다 |
| U2 | 읽어도 종 아이콘 숫자가 그대로 | ✗ | **필수** | 목록은 읽음으로 바뀌어 반응이 있다. 배지 숫자가 읽지 않은 알림 수라는 걸 알아야 한다 |
| N1 | 커뮤니티를 옮겨도 글 목록이 그대로 | ✗ | **필수** | 주소 · 머리글이 바뀌고 링크 글자와 제목도 맞는다. 글 목록이 다른 커뮤니티 것이라는 건 글의 커뮤니티를 봐야 안다 |
| N2 | 로그아웃 후 뒤로 가기로 쪽지가 보임 | ✗ | **필수** | 뒤로 가기가 직전 주소로 정상 이동한다. 로그아웃했으면 그 화면이 보이면 안 된다는 걸 알아야 한다 |

# F — 기능적 결함

**동작의 결과**가 잘못된 것만 넣는다. 입력값을 거르는 문제는 `V`,
보이는 모양은 `U`, 화면 이동은 `N` 이다. 네 건 모두 한 화면만 봐서는
정상처럼 보이고, 여러 단계 · 여러 계정을 오가며 앞뒤 상황을 맞춰 봐야
드러난다.

## F1 — 탈퇴한 커뮤니티의 글이 홈 피드에 계속 나옴

홈 피드가 로그인하는 순간의 가입 목록을 다음 로그인까지 계속 쓴다.
커뮤니티에서 탈퇴하면 홈 머리글의 "가입한 커뮤니티 N곳" 과 가입 칩 줄은
하나 줄어드는데, 피드에는 그 커뮤니티 글이 계속 섞여 나온다. 반대로 새로
가입한 곳의 글은 나오지 않는다. 로그아웃 후 다시 로그인하면 맞춰진다.

1. bob 으로 로그인한다.
2. `c/games` 에서 "가입됨" 을 눌러 탈퇴한다.
3. 홈으로 간다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 머리글 가입 목록 | games 없음 | games 없음 |
| 피드의 c/games 글 (첫 화면) | 0 | **2** |

```js
const me = (await (await fetch("/api/session")).json()).user;
const home = await (await fetch("/api/posts?feed=home")).json();
home.items.filter((p) => !me.joined.includes(p.community)).map((p) => p.community);
// 정상 []  ·  결함 ["games", "games"]
```

흔한 원인: 로그인 때 만든 값을 세션에 캐시해 두고, 가입 · 탈퇴 때 캐시를
비우지 않는다.

심은 자리: `server/api.ts` listPosts (feed=home), `server/auth.ts` startSession

## F2 — 다른 계정의 "최근 본 글" 이 보임

최근 본 글의 기록 이름을 아이디가 아니라 회원 / 손님 구분으로만 만든다.
같은 브라우저에서 로그아웃하고 다른 계정으로 들어오면, 앞 계정이 본 글이
홈 오른쪽 "최근 본 글" 에 그대로 나온다. 손님 기록은 정상처럼 따로 남는다
(로그아웃한 손님 화면에는 나오지 않는다).

1. alice 로 로그인해 글 두 개를 연다.
2. 로그아웃하고, 같은 창에서 bob 으로 로그인해 홈을 연다.
3. bob 이 본 적 없는 alice 의 글이 오른쪽 "최근 본 글" 에 있다.

```js
Object.keys(localStorage).filter((k) => k.startsWith("agora.recent."));
// 정상 ["agora.recent.alice", ...]  ·  결함 ["agora.recent.member"]
```

흔한 원인: 공용 기기에서 사용자별 저장 공간의 키에 사용자 ID 를 넣지
않는다.

심은 자리: `src/lib/recent.ts`

## F3 — 답글 알림을 꺼도 "내 댓글에 달린 답글" 알림은 계속 옴

설정의 "답글 알림" 은 "내 글에 댓글, 내 댓글에 답글이 달리면 알려
드려요" 라고 하는데, 끄면 "내 글에 달린 댓글" 알림만 멈추고 "내 댓글에
달린 답글" 알림은 계속 쌓인다. 설정 확인이 알림 종류 하나에만 들어가 있다.

1. carol 로 설정 > 알림에서 "답글 알림" 을 끈다.
2. 다른 계정(bob)으로 carol 의 댓글에 답글을 단다.
3. carol 의 알림에 "내 댓글에 답글을 남겼어요" 가 새로 와 있다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| carol 의 새 알림 | 없음 | **답글 알림 1건** |

흔한 원인: 설정 하나가 알림 종류 여럿을 묶는데, 확인하는 조건에는 한
종류만 적는다.

심은 자리: `server/notify.ts`

## F4 — 활동 정지된 사용자가 답글은 달 수 있음

활동 정지 검사가 새 댓글에만 걸리고 답글(다른 댓글에 다는 댓글)에는 빠져
있다. 정지 안내는 "글과 댓글을 쓸 수 없어요" 인데, 답글로 달면 그대로
등록되어 모두에게 보인다.

1. 시드에서 dave 는 `c/food` 에서 활동 정지 상태다. dave 로 로그인한다.
2. `c/food` 글에 새 댓글을 달면 거부된다 (정상과 같다).
3. 같은 글의 다른 사람 댓글에서 "답글" 을 눌러 달면 등록된다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 새 댓글 | 거부 | 거부 |
| 답글 | 거부 | **등록됨** |

흔한 원인: 같은 권한 검사를 여러 진입점에 따로 넣다가 한 곳을 빠뜨린다.

심은 자리: `server/api.ts` `POST /api/posts/:id/comments`

# V — 입력 검증 결함

입력값을 받아들이거나 거르는 판단이 틀린 것만 넣는다. 두 건 모두
**올바른 값을 거부한다.** 거부 메시지가 뜨는 것은 정상 동작이라, 메시지
내용과 넣은 값을 맞춰 봐야 결함인지 안다.

## V1 — 하이픈을 넣은 휴대전화 번호를 거부함

전화번호 입력 칸의 안내는 `010-1234-5678` 형식인데, 서버가 하이픈을 떼지
않고 검사해서 하이픈을 넣은 번호를 거부한다. 거부 메시지의 예시가 방금
넣은 형식과 같다. 숫자만 넣으면 통과한다.

1. 로그아웃 상태에서 로그인 > "전화번호로 계속하기" 를 누른다.
2. `010-1111-1111` 을 넣고 인증번호 받기를 누른다.

| 넣은 값 | 정상 | 결함 |
|---|---|---|
| `010-1111-1111` | 인증번호 발송 | **"휴대전화 번호를 확인해 주세요. 예: 010-1234-5678"** |
| `01011111111` | 인증번호 발송 | 인증번호 발송 (alice 로 로그인) |

흔한 원인: 입력을 정규화(공백 · 하이픈 제거)하기 전에 형식 검사를 한다.

심은 자리: `server/otp.ts` normalizeTarget (휴대전화)

## V2 — 한글이 들어간 링크 주소를 거부함

링크 주소 검사 정규식이 영어 · 숫자 · 일부 기호만 받는다. `https://` 로
시작하는 올바른 주소라도 경로나 도메인에 한글이 있으면 거부한다. 영어로만
된 주소는 통과한다.

1. 로그인한 뒤 글쓰기에서 커뮤니티를 고르고 제목을 쓴다.
2. 링크 붙이기에 `https://ko.wikipedia.org/wiki/서울` 을 넣고 등록한다.

| 넣은 값 | 정상 | 결함 |
|---|---|---|
| `https://ko.wikipedia.org/wiki/서울` | 등록 | **"http:// 또는 https:// 로 시작하는 주소를 넣어 주세요."** |
| `https://example.com/seoul` | 등록 | 등록 |

거부 메시지가 "http:// 또는 https:// 로 시작하라" 고 하는데 넣은 주소는
이미 `https://` 로 시작한다.

흔한 원인: 주소 검사를 영문 문자 집합만 받는 정규식으로 짠다.

심은 자리: `server/api.ts` `POST /api/posts` (링크)

# U — UI 결함

**데이터와 동작은 정상이고 화면 표시만 틀린** 것을 넣는다. 서버에 저장된
값을 보면 맞는데, 사용자가 보는 글자나 숫자가 다르다.

## U1 — 댓글을 신고하는데 창 제목이 "글 신고하기"

글과 댓글이 신고 창 하나를 같이 쓰는데, 제목을 정할 때 댓글 구분을 보지
않아 댓글의 "신고" 를 눌러도 제목이 "글 신고하기" 로 나온다. 신고 자체는
댓글로 제대로 접수된다.

1. 로그인한 뒤 아무 글에서 다른 사람 댓글의 "신고" 를 누른다.
2. 창 제목을 본다.

| 연 곳 | 정상 | 결함 |
|---|---|---|
| 글 오른쪽 위 메뉴 > 신고 | 글 신고하기 | 글 신고하기 |
| 댓글의 신고 | 댓글 신고하기 | **글 신고하기** |
| 접수된 신고의 대상 | 댓글 | 댓글 |

흔한 원인: 공용 컴포넌트에 분기가 늘어나면서 제목 조건 하나를 고치지
않는다.

심은 자리: `src/components/ReportDialog.tsx`

## U2 — 알림을 읽어도 종 아이콘의 빨간 숫자가 그대로

알림을 읽음 처리한 뒤 머리글의 읽지 않은 알림 수를 다시 불러오지 않는다.
알림 목록은 모두 읽음으로 바뀌고 알림 화면 머리글의 숫자도 줄어드는데,
종 아이콘의 빨간 숫자는 그대로 남는다. 새로고침하거나 다른 동작(가입 ·
글쓰기 등)으로 로그인 정보를 다시 받으면 맞춰진다.

1. alice 로 로그인한다 (읽지 않은 알림이 있다).
2. 종 아이콘을 눌러 "모두 읽음으로 표시" 를 누르거나 알림 하나를 연다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 알림 목록 | 모두 읽음 | 모두 읽음 |
| 서버의 읽지 않은 수 | 0 | 0 |
| 종 아이콘 숫자 | 사라짐 | **16 그대로** |

```js
(await (await fetch("/api/session")).json()).user.unread.notifications;   // 0
document.querySelector('button[aria-label="알림"]')?.textContent;          // 결함 "16"
```

흔한 원인: 목록의 상태만 바꾸고, 다른 곳에 있는 집계 값(배지)은 다시
불러오지 않는다.

# N — 이동 · 라우팅 결함

화면을 옮길 때 무엇이 보이는지가 틀린 것을 넣는다. 두 건 모두 **주소는
맞게 바뀐다.** 404 도 없고, 뒤로 가기도 직전 주소로 돌아간다. 틀린 것은
그 주소에서 보이는 내용이다.

## N1 — 다른 커뮤니티로 옮겨도 이전 커뮤니티의 글 목록이 남음

커뮤니티 화면에 머문 채 다른 커뮤니티로 옮기면(검색 자동 완성 클릭, 뒤로 ·
앞으로 가기) 주소 · 머리글 · 소개 · 말머리는 새 커뮤니티로 바뀌는데, 글
목록은 다시 불러오지 않아 처음 연 커뮤니티의 글이 그대로 남는다. "더 보기"
를 누르면 새 커뮤니티 글이 이어 붙어 섞이고, 정렬 탭을 누르거나
새로고침하면 맞춰진다.

1. `c/games` 화면을 연다.
2. 머리글 검색창에 "음악" 을 입력하고, 자동 완성에 뜬 `c/music` 을 클릭한다.
3. 뒤로 가기(`c/games`) 한 뒤 앞으로 가기로 `c/music` 에 다시 온다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 주소 | `/c/music` | `/c/music` |
| 머리글 · 소개 | 음악 | 음악 |
| 글 목록 | c/music 글 | **c/games 글** |

글 목록 위쪽은 모두 맞아서, 글마다 붙은 커뮤니티 이름을 봐야 틀린 걸
안다.

흔한 원인: 데이터를 불러오는 효과(effect)의 의존성 목록에서 주소 값
하나가 빠진다. 같은 컴포넌트가 재사용되어 다시 불러오지 않는다.

심은 자리: `src/components/Feed.tsx`

## N2 — 로그아웃 후 뒤로 가기로 쪽지함 · 설정이 그대로 보임

로그인이 필요한 화면의 로그인 확인이 브라우저 뒤로 · 앞으로 가기 이동에서는
건너뛰어지고, 화면은 서버가 "로그인이 필요해요" 로 거부하면 마지막으로 받은
응답을 대신 보여 준다. 그래서 로그아웃한 뒤 뒤로 가기를 누르면 로그인
화면으로 가지 않고, 머리글은 로그아웃 상태인데 본문에는 직전 사용자의 쪽지
목록 · 대화 · 설정이 보인다.

1. alice 로 로그인해 쪽지함(`/messages`)에서 bob 과의 대화를 연다.
2. 오른쪽 위 메뉴 > 로그아웃 (홈으로 이동한다).
3. 브라우저 뒤로 가기를 누른다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 주소 | 로그인 화면 | `/messages/bob` |
| 머리글 | 로그인 버튼 | 로그인 버튼 |
| 본문 | 로그인 양식 | **alice 와 bob 의 대화** |
| 그 화면에서 쪽지 보내기 | — | "로그인이 필요해요" 로 실패 |
| 새로고침 | — | 로그인 화면으로 감 |

로그아웃 자체는 정상이라 서버는 요청을 거부한다. 화면에 남은 것은 이전에
받아 둔 응답이다.

흔한 원인: 뒤로 가기 때 보호 화면의 로그인 확인을 건너뛰거나, 실패한 요청
대신 캐시해 둔 응답을 보여 준다.

심은 자리: `src/components/RequireLogin.tsx`, `src/lib/api.ts`
