# 주입한 결함 목록 (F · V · N · U)

레지스트리 네 파일에 등록된 **12건**의 증상과 확인 방법을 한곳에 모았다.
레지스트리(`server/bugs/*.ts`)는 기계가 읽는 자리(정답지 생성)이고, 이 문서는
사람이 읽는 자리다. 증상 · 재현 절차 · 확인용 API 호출은 여기에 둔다.

| 접두사 | 분야 | 건수 | 레지스트리 | 브랜치 |
|---|---|---|---|---|
| `F` | 기능적 | 4 | `server/bugs/functional.ts` | `feature/bugs-functional` |
| `V` | 입력 검증 | 3 | `server/bugs/validation.ts` | `feature/bugs-validation` |
| `N` | 이동 · 라우팅 | 2 | `server/bugs/routing.ts` | `feature/bugs-routing` |
| `U` | UI | 3 | `server/bugs/ui.ts` | `feature/bugs-ui` |

```sh
npm run dev           # 정상본 — 기준선 (8094)
npm run dev:bugs      # 12건 전부 (8095, DB 파일 따로)
BUG_F2=1 npm run dev  # 한 건만
```

```
GET  /api/bugs    지금 켜진 ID 목록 (정상본은 빈 목록)
GET  /gt.json     정답지 (레지스트리에서 생성한다. 손으로 쓰지 않는다)
POST /_reset      사용자가 바꾼 서버 상태 전부(계정 · 세션 · 관심 단지 · 저장한 검색 · 최근 본 단지 ·
                  예산 · 계획 · 매물 · 메시지 · 문의)를 시드로 되돌린다. 실거래가 자료는 읽기 전용이라 그대로
```

**배포 주소** — 정상본 http://54.180.42.43:8002 (main), 결함본 http://54.180.42.43:8003
(develop, 12건 전부 켬). 두 판은 DB 파일과 로그인 쿠키 이름이 달라 같은 브라우저에서
번갈아 열어도 섞이지 않는다. 평가 한 회가 끝나면 두 주소에 각각 `POST /_reset` 을 보낸다.

**평가는 12건을 전부 켠 상태로 한다.** 아래 재현 절차는 정상본과 전부 켠 판을
같은 절차로 돌려 확인한 것이다. 한 결함만 보여줘야 할 때만 `BUG_U2=1` 처럼
한 건씩 켠다.

테스트 계정은 README 의 "테스트 계정" 과 같다.

| 이메일 | 비밀번호 | 쓰임 |
|---|---|---|
| demo@jipteo.kr | jipteo1234 | 관심 단지 3곳(마포구) · 메시지 · 계획이 들어 있는 회원 |
| tester@jipteo.kr | tester1234 | 관심 단지 0 · 안 읽은 메시지 1통인 빈 회원 |

정상본과 결함본을 같은 브라우저에서 번갈아 열 때 로그인은 포트마다 따로 한다
(쿠키 이름이 `jipteo_session` · `jipteo_session_alt` 로 다르다). V1 · V3 로
만든 매물과 V2 로 만든 계정은 결함본 DB 에 남으니 확인 뒤 `POST /_reset`.

# 규칙으로 잡히는가 — 한눈에 보기

## 판정 기준

**규칙** — 그 화면의 정답을 코드에 적어 넣지 않고, 어느 사이트에나 통하는
결정적인 검사로 "이상하다" 는 신호를 낼 수 있으면 규칙으로 잡힌다. 깨진 링크 ·
404 · 콘솔 오류 · 빈 응답 · 글자 넘침 · 대비 부족이 그렇다.

**AI** — 규칙이 낼 신호가 아예 없고, 화면이 정상으로 보이며, 이상하다는 걸
알려면 **기대 동작 · 도메인 상식 · 다른 화면의 사실**을 알아야 하면 AI 가
필요하다.

## 12건 판정

12건 모두 **AI 필수**다. 결함을 고를 때 규칙에 걸리는 것(오류 메시지 · 콘솔 ·
404 · 레이아웃 깨짐)은 뺐고, 레지스트리에도 모두 `detectable: false` 로 적혀 있다.

| ID | 결함 | 필요한 판단 |
|---|---|---|
| F1 | 최고가 경신에 계약 해제 거래가 들어감 | 시세 산정 문서의 규칙 + 거래 내역의 취소선 읽기 |
| F2 | 평당 가격 환산 상수 3.3 (정확히는 3.3058) | 1평 = 3.3058㎡ 상식, 0.2% 오차 검산 |
| F3 | 새 소식의 관심 단지 소식이 다른 회원 것 | 두 계정 오가며 관심 단지와 소식 대조 |
| F4 | 경기 규제지역 LTV 를 70% 로 계산 | 같은 화면 안내문(규제지역 40%)과 결과 모순 |
| V1 | 희망 가격 상한 없음 | 안내문 범위 읽고 경계 밖 값 넣어 보기 |
| V2 | 비밀번호 확인란 미비교 | 확인란의 목적 이해, 일부러 다르게 넣기 |
| V3 | 층수가 최고층 넘어도 통과 | 단지 상세의 최고층과 입력값 대조 |
| N1 | 로그인 뒤 첫 화면으로 감 | 로그인 전 위치 기억 |
| N2 | 조건 변경이 뒤로 가기에 안 남음 | 여러 번 조작 뒤 뒤로 가기 관찰 |
| U1 | 카드 면적 단위 ㎡ · 평 뒤바뀜 | 84평 집이 25㎡ 일 수 없다는 상식 |
| U2 | 읽어도 안 읽은 수 그대로 | 행동 전후 상태 비교 |
| U3 | 긴 이름 잘려 1차 · 2차 · 3차 구분 불가 | 말줄임이 뜻을 가렸는지, 상세 제목과 대조 |

# F — 기능적 결함

**동작의 결과**가 잘못된 것만 넣는다. 입력값을 거르는 문제는 `V`, 화면 이동은
`N`, 자료는 맞는데 보이는 모양만 틀린 것은 `U` 다.

## F1 — 최고가 경신 판정에 계약 해제 거래가 들어감

시세 산정 방식 문서는 "계약 해제 거래는 통계에서 뺀다" 고 하지만, 최고가 경신
판정이 해제된 고가 거래도 비교 대상에 넣는다. 해제된 거래보다 낮은 진짜 최고가
거래에 "최고가 경신" 표시가 붙지 않는다.

1. 머리글 **실거래가** → 시도 **인천** · 시군구 **연수구** → 검색창에 `롯데캐슬캠퍼스타운`.
2. 표에서 **2026.10.23 · 101㎡ · 8억 8,700** 줄의 "구분" 열을 본다.
3. 단지 이름을 눌러 상세로 가면 101㎡ 거래 내역에 해제된 더 비싼 거래(2026.08.29 9억 400, 취소선)가 있다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 구분 열 | 최고가 경신 | **중개거래** |

```
GET /api/deals?sido=28&sgg=28185&q=롯데캐슬캠퍼스타운
→ items 중 deal.date="2026-10-23", areaM2≈101 인 행의 record  (정상 true · 결함 false)
```

흔한 원인: 통계 계산에서 "해제 제외" 조건을 한 곳(여기서는 비교 대상 쪽)에만 빠뜨린다.

심은 자리: `server/data/complexes.ts` isRecord()

## F2 — 평당 가격의 ㎡→평 환산 상수가 3.3058 이 아니라 3.3

평당 가격이 1평 = 3.3058㎡ 가 아니라 3.3㎡ 로 환산돼 약 0.18% 낮다. 같은 줄의
㎡당 가격과 카드의 평 표기(3.3058 기준)는 정상이라 둘이 서로 맞지 않는다. 평당
가격이 보이는 모든 곳(카드 · 상세 요약 · 거래 내역 표 · 실거래가 표)에서 같다.

1. 머리글 **매매** → 지도에서 **경기** → **용인시 수지구** → 첫 카드 **진산마을삼성5차** 를 눌러 상세로.
2. 요약 칸 "평당 가격" 과 그 옆 "㎡당" 을 본다. 최근 실거래가 14억 7,000 · 전용 84.21㎡.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 평당 가격 | 5,771만 (= 147,000 ÷ (84.21 ÷ 3.3058)) | **5,761만** (= 147,000 ÷ (84.21 ÷ 3.3)) |
| 검산 ㎡당 1,746만 × 3.3058 | 5,772만 ≈ 평당 | 평당과 10만 원 어긋남 |

흔한 원인: 평 환산 상수를 3.3 으로 근사해 쓴다. 실무에서 매우 흔하고 눈에 잘 안 띈다.

심은 자리: `src/lib/format.ts` perPyeong()

## F3 — 새 소식의 관심 단지 소식이 다른 회원 것

새 소식의 "관심 단지 소식" 이 로그인한 회원이 아니라 회원 번호 1(demo)의 관심
단지로 만들어진다.

1. **tester@jipteo.kr / tester1234** 로 로그인한다.
2. 왼쪽 **관심 단지** 는 "아직 담은 단지가 없어요".
3. 왼쪽 **새 소식** 의 "관심 단지 소식" 을 본다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 관심 단지 소식 | 비어 있음 | **마포구 단지 소식 5건** (상암월드컵파크3단지 · 일신건영휴먼빌 · 해모로 = demo 의 관심 단지) |

```
GET /api/updates  (tester 로그인 쿠키)
→ personal.length  (정상 0 · 결함 5)
```

흔한 원인: 디버깅 때 넣은 고정 사용자 ID, 또는 세션 대신 기본값을 쓰는 실수.

심은 자리: `server/routes/member.ts` GET /api/updates

## F4 — 대출 계산이 경기 규제지역을 수도권 비규제(LTV 70%)로 봄

지역 구분이 경기도 안 시군구를 무시해 규제지역(과천 · 분당 · 수지 등 12곳)도
LTV 70% · 한도 6억으로 계산한다. 바로 위 안내문 "규제지역(서울 전역 · 경기
12곳)은 LTV 가 40%예요" 와 모순된다. 서울은 정상.

1. **진산마을삼성5차**(경기 용인시 수지구) 단지 상세 → **이 가격으로 대출 계산하기**.
2. 지역이 경기 · 용인시 수지구, 매매가 14억 7,000, 무주택으로 채워진다. 매매가 아래 한도 상자를 본다.
3. 머리글 **대출 계산** 에서 지역을 경기 → 과천시 · 성남시 분당구 등으로 직접 골라도 같다. 서울 아무 구는 정상본과 같다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 한도 상자 | 규제지역 · LTV 40% · 한도 6억 → 최대 대출 5억 8,800 | **수도권 (비규제) · LTV 70% · 한도 6억 → 최대 대출 6억** |

흔한 원인: 시도 단위 규칙을 먼저 만들고 시군구 예외를 나중에 붙이다 빠뜨린다.

심은 자리: `src/features/loan/LoanPage.tsx` zone 계산

# V — 입력 검증 결함

형식(숫자 · 길이)은 모두 통과하지만 값의 뜻으로는 막아야 할 입력을 통과시킨다.
화면 검증과 서버 검증이 같은 함수를 쓰므로 둘 다 같이 빠져 있다.

## V1 — 내 집 내놓기 희망 가격에 상한이 없음

희망 가격은 100억 원 이하여야 하는데 상한 검사가 빠져 950억 같은 값도 등록된다.

1. 로그인 → 머리글 **내 집 내놓기**.
2. 단지 **진산마을삼성5차**, 동 `101`, 호 `1203`(층은 12 로 자동), 전용면적 선택, 희망 가격 `9500000`(950억), 연락처 `010-1234-5678` → **매물 등록하기**.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 희망 가격 칸 | "희망 가격은 1,000만 원 이상 100억 원 이하로 입력해 주세요." | **등록됨**, 오른쪽 목록에 950억 매물 |

흔한 원인: 하한만 검사하고 상한을 빠뜨린다.

심은 자리: `shared/forms.ts` validateListing() `noPriceCap` (화면 · 서버 공통)

## V2 — 회원가입에서 비밀번호 확인란을 비교하지 않음

비밀번호와 확인이 달라도 가입된다. 두 칸 모두 "영문 + 숫자 8자 이상" 형식은
지키므로 다른 오류는 없다.

1. 로그아웃 상태 → 머리글 **로그인** → **회원가입**.
2. 새 이메일, 이름, 비밀번호 `test1234`, 비밀번호 확인 `test5678`, 약관 동의 → **가입하기**.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 확인란 아래 | "비밀번호가 서로 달라요." | **가입 완료** → 첫 화면, 머리글에 이름 |

흔한 원인: 검증 함수를 손보다 비교 한 줄이 빠진다.

심은 자리: `src/features/auth/SignupPage.tsx` validate()

## V3 — 매물 층수가 단지 최고층을 넘어도 통과

정상본은 건축물대장 최고층(단지 상세 "단지 정보") 보다 높은 층을 막는데,
결함본은 1~99 범위만 본다.

1. 로그인 → 머리글 **내 집 내놓기** → 단지 **진산마을삼성5차**(최고층 19층).
2. 호 `1203` 을 넣으면 층이 12 로 채워진다. 층 칸을 지우고 `25` 로 고친다. 나머지 정상 입력 → **매물 등록하기**.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 층 칸 | "이 단지의 최고층은 19층이에요 (건축물대장)." | **등록됨** |

흔한 원인: 범위 검사(1~99)만 하고 실제 대상(그 단지)과의 의미 검사를 빠뜨린다.

심은 자리: `shared/forms.ts` validateListing() maxFloor 인자 (화면 · 서버 공통)

# N — 이동 · 라우팅 결함

링크가 깨지거나 404 가 나는 것이 아니라, 멀쩡한 화면이 열리는데 기대한 곳과
다르다.

## N1 — 로그인 뒤 하던 화면으로 돌아오지 않고 첫 화면으로 감

로그인 주소의 next 를 무시해 로그인이 끝나면 항상 첫 화면으로 간다.

1. 로그아웃 상태 → 머리글 **내 집 내놓기** → 잠금 안내의 **로그인하기**.
2. demo@jipteo.kr / jipteo1234 로 로그인한다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 로그인 뒤 화면 | 내 집 내놓기 | **첫 화면** |

흔한 원인: 로그인 흐름에서 돌아갈 주소(next) 처리를 빠뜨린다.

심은 자리: `src/features/auth/AuthProvider.tsx` safeNext()

## N2 — 검색 조건을 바꾼 기록이 뒤로 가기에 남지 않음

가격 · 면적 · 준공 연도 · 필터 조건을 바꿀 때 주소를 교체(replace)해, 뒤로
가기를 누르면 조건이 한 단계씩 풀리지 않고 검색 화면 밖으로 나간다. 지역 선택은
정상적으로 기록에 남는다.

1. 첫 화면 → 머리글 **매매** → 지도에서 **경기** 클릭.
2. 검색 줄 **가격** → 최대 5억 → 다시 최대 10억.
3. 브라우저 **뒤로 가기**.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 뒤로 가기 뒤 | 가격 최대 5억 상태 | **첫 화면** (검색 화면을 벗어남) |

흔한 원인: 필터 변경에 `history.replace` 를 써서 중간 상태가 기록에 남지 않는다.

심은 자리: `src/features/search/useSearchState.ts` write()

# U — UI 결함

자료 · API 는 맞는데 화면이 다르게 보여 주는 것만 넣는다.

## U1 — 단지 카드의 면적 단위 글자가 서로 바뀜

카드 면적 줄이 "전용 84㎡ · 25.5평" 이어야 하는데 단위만 바뀌어 "전용 84평 ·
25.5㎡" 로 보인다. 숫자는 정상. 카드가 나오는 모든 곳(첫 화면 · 매매 검색 ·
관심 단지 · 단지 상세 아래 다른 단지)에서 같고, 단지 상세 요약 · 면적 탭 ·
실거래가 표는 정상이다.

1. 머리글 **매매** → **경기** → **용인시 수지구** → 첫 카드 **진산마을삼성5차** 의 면적 줄.
2. 카드를 눌러 상세의 면적 탭 "84㎡ (25.4평)" 과 비교한다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 카드 면적 줄 | 전용 84㎡ · 25.5평 · 5층 · 2003년 | **전용 84평 · 25.5㎡** · 5층 · 2003년 |

흔한 원인: 단위 라벨을 상수로 빼다 순서를 바꿔 넣는다.

심은 자리: `src/components/listing/ComplexCard.tsx` Specs()

## U2 — 메시지를 읽어도 안 읽은 메시지 수가 줄지 않음

메시지를 열면 본문이 열리고 목록의 읽음 표시(주황 점)도 사라지지만, 왼쪽 아이콘
줄 "메시지" 의 빨간 숫자는 그대로다. 새로 고침해야 줄어든다.

1. **tester@jipteo.kr / tester1234** 로 로그인 → 왼쪽 아이콘 줄 **메시지** 에 빨간 1.
2. 메시지함에서 안 읽은 메시지("이테스트님, 집터에 오신 걸 환영해요") 클릭.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 아이콘 줄 숫자 | 바로 사라짐 | **1 이 남음** (F5 하면 사라짐) |

흔한 원인: 전역 상태(안 읽은 수)를 화면 상태와 따로 들고 있다가 한쪽만 갱신한다.

심은 자리: `src/features/inbox/InboxPage.tsx` 메시지 열기 effect

## U3 — 카드의 긴 단지 이름이 잘려 1차 · 2차 · 3차가 같은 단지로 보임

카드가 이름을 12자에서 "…" 로 잘라 "버들치마을성복힐스테이트1차 · 2차 · 3차" 가
모두 "버들치마을성복힐스테이트…" 로 보인다. 가격 · 면적 · 번지는 각자 맞아서
"같은 단지가 값만 다르게 세 번" 처럼 읽힌다. 이름이 12자 이하인 단지는 정상이라,
잘리는 길이에 따라 어떤 쌍은 구분되고 어떤 쌍은 안 된다.

1. 머리글 **매매** → **경기** → **용인시 수지구** → 검색창에 `버들치마을`.
2. 카드 7장 중 힐스테이트 세 장의 이름을 본다. 각 카드를 누르면 상세 제목에 1차 · 2차 · 3차가 있다.
3. 같은 화면의 "버들치마을성복자이1차 · 2차"(11자)는 두 판 모두 구분된다. 충남 아산시 `지웰시티` 로 검색해도 같다.

| 봐야 할 곳 | 정상 | 결함 |
|---|---|---|
| 카드 이름 | 버들치마을성복힐스테이트1차 · 2차 · 3차 | **셋 다 "버들치마을성복힐스테이트…"** (성복동 771 / 759 / 760) |

흔한 원인: 한 줄 맞춤을 위해 이름을 글자 수로 자르면서 뒤쪽 구분자를 함께 잘라 낸다.

심은 자리: `src/components/listing/ComplexCard.tsx` cardName()

# 코드에서 찾기

주입 지점마다 조건과 주석이 같이 있다.

```
isOn("F1")   서버 (server/bugs/index.ts)
bugOn("U1")  화면 (src/lib/bugs.ts) — 첫 렌더 전에 GET /api/bugs 를 받아 둔다 (src/main.tsx)
// [F1] 결함: …
```

`git diff main develop` 이 결함 주입 전체이고, 분야별로는 각 `feature/bugs-*`
브랜치의 커밋 하나가 그 분야의 주입 전부다.
