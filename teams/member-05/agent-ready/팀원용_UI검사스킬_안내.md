# 팀원용 UI 검사 스킬 안내

**팀원은 이 문서, 검사 에이전트는 [SKILL.md](ui-bug-inspector/SKILL.md) 하나를 보시면 됩니다.** 정상 사이트와 비교하지 않고 검사 대상 사이트의 현재 화면과 동작으로 UI 결함을 판단하는 지침입니다.

## 팀원에게 전달할 소개 문구

> UI 버그의 미탐과 불필요한 판정 보류, 반복적인 AI 호출을 줄이기 위한 검사 지침을 정리했습니다. 정상 사이트와 비교하는 방식은 사용하지 않습니다. 같은 사이트에서 테마·메뉴·화면 크기 등 필요한 상태를 검사하고, 실제 읽기나 조작에 문제가 있는지 증거로 판단합니다. 에이전트에는 SKILL.md 한 파일만 UI 검사 단계에 연결하면 됩니다. 현재는 문서와 판정 절차를 검토한 상태이며, 성능과 비용 개선은 프로토타입에서 확인해야 합니다.

## 핵심으로 볼 세 가지

| 목표 | 스킬이 시키는 일 |
|---|---|
| UI 미탐 줄이기 | 초기 화면뿐 아니라 테마·메뉴·스크롤·오류 상태를 확인하고, DOM이 정상이어도 실제 화면을 검사 |
| 불필요한 보류 줄이기 | 필요한 증거가 모이면 판정을 끝내고, 부족하면 결론을 바꿀 다음 확인 하나만 수행 |
| 낭비 줄이기 | 같은 증거 재질문·중복 재현을 줄이고, 준비 실패가 독립 검사까지 막지 않게 처리 |

확정에는 **대상/상태·기대 근거·실제 손실·관련 정상 예외 확인·동일 실패 조건 재현**이 필요합니다. 원인 코드·수정법·다른 기기의 발생 여부를 모른다는 이유만으로 이미 입증한 결함을 보류하지 않습니다. 반대로 근거 부족을 억지 확정으로 바꾸지 않습니다.

## 검사 범위와 리포트 반영

기본 범위는 가독성·겹침·넘침·반응형·이미지/아이콘·메뉴·문구 잘림·폼 안내·필수 요소 표시입니다. 기능·라우팅·서버 입력 검증은 다른 검사와 구분합니다. 키보드·확대 검사는 요청된 범위에서 수행합니다.

[제공된 보고서](C:/Users/applepen/Downloads/report%20%281%29.pdf)의 UI 내용을 다음처럼 반영했습니다.

| 기록 | 적용한 개선 |
|---|---|
| Email/Compose 다크 테마의 글자·아이콘 표시 손실 | UI-015: 테마별 제목·활성 버튼·입력값·안내·아이콘 가독성 |
| 계정 메뉴의 Logout/Switch Account 글자 겹침 | UI-001: 메뉴 내부 읽기 손실과 정상 배경 가림 구분 |
| DOM에는 있으나 보이지 않는 Compose 링크 메모 | UI-014: 활성·접힘·화면 밖·대체 경로 확인 |
| 취소 후 이전 오류 안내가 남는다는 메모 | UI-012: 현재 상태와 안내의 모순 확인; 잔존 자체는 결함 아님 |
| 메뉴/Compose 시작 조건 준비 실패 | 미확인을 false로 해석하지 않고 실제 상태 재확인; 실패한 준비에 의존하는 검사만 미검사 |

보고서에는 UI 시각 판정 3건, 전체 실행의 판단 보류 0건·판정 못 함 8건이 있습니다. 메뉴/Compose의 UI 관련 준비·후속 검사 6건이 미완료였고, 나머지 입력 검증 관련 2건은 이번 UI 보강 범위에서 제외했습니다. 모든 미완료를 UI 버그나 판단 보류로 세지 않습니다.

보고서 화면과 기록은 확인했지만 원본 브라우저에서 재현하지 않았습니다. 탐색 메모를 새 확정 결함으로 승격하지 않았고, 글자를 읽기 어려운 것을 실제 클릭 불가로 확대하지 않았습니다.

## 적용 방법

UI 검사 호출에 **기존 팀 공통 지침 + SKILL.md 본문 + 현재 검사 증거**를 전달합니다. 일반 API는 로컬 경로만으로 파일을 읽지 않으므로 호출 측이 본문을 넣어야 합니다. 스킬 런타임에서는 폴더를 등록하고 파일을 읽게 합니다.

- 유형별 파일 선택이나 보류 때 추가 파일 로딩은 없습니다.
- 사람용 문서·평가 정답은 에이전트 입력에서 제외합니다.
- 크롤러·입력 검증·보고서 등 다른 팀원 담당의 모든 호출에 이 지침을 추가하지 않습니다.
- 기존 권한·예산·출력 필드를 유지합니다. 명시된 판정 이름은 기존 필드에 의미를 대응하며 새 스키마를 강제하지 않습니다.
- 같은 사이트의 테마/메뉴/폭 변경은 상태 검사입니다. 이전 화면이나 다른 사이트를 정상 정답으로 삼지 않습니다.

## 최종 검토 결과와 확인할 일

지침은 한 파일에서 외부 참조 없이 사용할 수 있도록 정리했습니다. 독립 검사의 시작 상태 복원, 후보별 추가 확인 상한, 기존 출력 계약과의 연결, DOM에서 아예 누락된 필수 요소 검사도 마지막 검토에 반영했습니다.

약 4,200자이며 문자 수는 토큰 수가 아닙니다. 한 파일로 연결은 단순해졌지만, 일부 규칙만 보내던 요청보다 입력이 커질 수 있어 비용 절감을 단정하지 않습니다. API 연결·실제 금액 제한·브라우저 실행 코드는 수정하지 않았습니다.

팀에서 최소한 다음을 확인하면 됩니다.

| 검증 상황 | 확인할 결과 |
|---|---|
| 표시 손상·예외 확인·재현은 있지만 원인을 모름 | 원인 미상만으로 보류하지 않음 |
| 메뉴 준비 실패, 다른 UI에는 접근 가능 | 독립 검사는 계속함 |
| 다크 테마로 이미 시작 | 토글 전에 현재 상태를 확인함 |
| 정상적인 팝업 배경 가림/줄바꿈 | 수치만으로 오탐하지 않음 |
| 안내가 남아 있지만 현재 상태에 유효함 | 잔존만으로 확정하지 않음 |
| 재현 근거 없음 | 같은 캡처를 두 번 해석해 확정하지 않음 |

평가자는 알려진 결함 정보를 따로 보관하고 한 사이트를 검사시킵니다. 동일 모델·도구·허용 상태·예산에서 정확도, 알려진 결함 누락, 보류/미검사/미완료, 실제 호출·토큰·비용을 함께 봅니다. **문서 검토는 완료했지만 Claude 실행과 성능/비용 개선 검증은 아직 하지 않았습니다.**
