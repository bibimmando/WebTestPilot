# 기존 기능을 하나의 서비스로 연결하는 설계
기준일: 2026-10-10 · 연결 관계와 사용자 경험 계획, 미구현

## 핵심 객체의 역할

| 객체/상태 | 현재/계획 | 원본 책임 | 다른 화면에서 사용하는 방법 |
|---|---|---|---|
| 개인 Task | id/title/done 현재, deadline/priority/source 계획 | Tasks 저장 경로 | 홈에는 일부 요약, 리포트는 기록된 완료시각, source는 원본 ID |
| Calendar event | 실제 shared/private·반복·RSVP·revision | Calendar | 홈/대기함/Agenda가 같은 접근 범위 사용 |
| Email entry | 사용자별 독립 사본·폴더/읽음 | 기존 Email | 홈 요약/검색/source link; reader에서 읽음/답장 |
| Chat room/message | shared/private·sequence·읽음 | 기존 Chat | 홈/검색/즐겨찾기/source link; 실제 read cursor는 Chat |
| 공개 구성원 | 일부 search 현재, 주소/목록 조회 계획 | 공개 directory DTO | 수신자/참석자/담당자/연락 카드 선택 |
| 활성 계정 | browser grant·현재 session 실제 | Auth/accounts | 개인 자료와 preference의 owner, tabs 공유 |
| 개인 preference | 테마 일부 현재, profile/home/timezone 계획 | 자기 settings | Home renderer/개인 방 표시/기본 시간대 |
| 확인할 항목 | source 상태 파생 뷰 계획 | 초대/task/unread 원본 | 별도 완료 사본 없이 원본 행동으로 해소 |
| 업무 요청 | 신규 조건부 계획 | 요청자/담당자의 request service | 대기함·연락 바로가기·후속 내 Task |
| 장소 | 신규 조건부 계획 | 허용된 장소 service | Calendar location 입력 재사용 |

## 흐름1: 메일 요청을 실제 업무로 이어가기

1. 홈 최근 Inbox에서 제목을 선택하면 같은 계정의 mailId reader를 연다.
2. reader에서 기존 내용을 확인하고 '할 일로 추가'를 선택한다.
3. 확인 창에서 제목/마감일을 사용자가 정한다. 메일 전문/주소 목록을 Task에 자동 복사하지 않는다.
4. 개인 Task 저장 후 reader에 '연결된 내 할 일 보기'가 표시된다.
5. Tasks에서 원본 링크로 같은 mail entry를 다시 연다. 원본 삭제/다른 계정 접근은 '사용할 수 없는 원본'으로 안내하며 task는 남는다.

공유로 받은 메일이라도 사용자별 entry ID/권한을 따른다. 원본이 없다고 전체 메일함을 자동 검색해 타인 사본에 연결하지 않는다. 같은 원본을 여러 후속 task로 나눌지 기본1개만 제안할지는 미결정이다. 추천 기본은 기존 연결을 먼저 보여 주고 사용자가 추가 업무를 명시하면 여러 개 허용이다.

## 흐름2: 일정·대화에서 후속 행동

홈의 다음 일정→기존 Calendar 상세→참석 응답/장소 확인. 참석자 옆 구성원 액션으로 메일/대화를 시작할 수 있다. Chat에서 특정 결정 메시지를 개인 task에 연결하고 나중에 message anchor로 앞뒤 맥락을 확인한다. 반복 일정 source는 시리즈 ID를 기본으로 하며 발생일을 함께 기록할 필요는 별도 결정한다. 현재 개별 occurrence 편집을 지원한다고 가정하지 않는다.

Calendar의 기존 Agenda를 새 표 페이지로 복제하지 않고 범위/검색/카테고리 상태를 같은 화면에서 유지한다. 요청에서 일정을 생성하는 경우 사용자의 검토 후 기존 일정 form을 열며 요청 등록만으로 공유 일정이 자동 생성되지 않는다.

## 흐름3: 구성원 발견과 연락

구성원에서 활성 계정을 검색→공개 표시명/내부주소→메일 작성·private1:1 대화·일정 참석자 선택. 기존 users/search는 self 제외/최대20/id·username·displayName 계약이므로 전체 연락처/주소 lookup을 직접 대체하지 못한다. 자기 profile 조회와 공개 연락처 API의 필드는 다르게 유지한다.

특정 구성원에게 메일을 써도 발신자는 현재 세션이고, 채팅은 기존 private pair 권한, 일정은 현재의 shared 생성 정책이다. 참석자를 선택한다고 그 일정이 private가 되는 것이 아니다. 작성 시 이 의미를 설명한다.

## 흐름4: 계정 전환과 미저장 내용

헤더의 현재 계정에서 기존 Switch Account를 연다. 메일/일정/Task 입력이 바뀐 상태면 그 상황을 미리 안내하고 사용자가 취소 또는 저장 가능한 초안을 보관한 뒤 전환할 수 있게 한다. Calendar에 초안 저장 기능이 없으므로 '모든 작성 내용 자동 보관'을 약속하지 않는다. 저장 불가능한 화면은 폐기 여부를 명확히 확인한다.

전환이 성공하면 기존 전체 reload·CSRF 회전·이전 요청 차단·WS/polling 정리를 유지한다. 새 계정의 private 자료/preference만 읽고 기존 shared 자료는 접근 정책에 맞게 표시한다. 탭별 활성 계정 독립·만료 시 조용한 자동 대체 전환은 신규로 넣지 않는다. server session 만료가 사용자 dirty dialog 때문에 무기한 지연되면 안 된다.

## 흐름5: 검색·확인할 항목·리포트

검색은 어떤 자료를 찾아야 하는지 아는 경우, 확인할 항목은 응답해야 할 것을 놓치지 않는 경우, 리포트는 업무를 돌아보는 경우를 담당한다. 같은 활동 기록을 세 메뉴에 복사해 서로 다른 완료 상태를 만들지 않는다.

확인할 항목의 read/done은 각 원본을 따른다. Calendar RSVP 처리·메일 읽음·Chat read·Task 완료가 실제 source에서 반영되어 목록이 갱신된다. 알림창을 닫았다는 이유만으로 모든 메일/대화를 읽음 처리하지 않는다. W03이 없으면 deadline 경고를 표시할 수 없으며 mention/push는 현재 원천이 없어 초기 범위에서 제외한다.

업무 리포트는 현재 리소스와 기록된 완료 이력을 구분한다. current Sent 폴더 기반 수치가 불변 발신 건수인 것처럼 보이지 않게 한다. 새 완료 기록 이전의 과거를 지어내지 않고, 메시지 수는 개인 업무 참고 정보이지 구성원 성과 평가 지표가 아니다.

## 미결정 정책

| 결정 | 권장 초기값 | 추가 확인 |
|---|---|---|
| 서비스 대상 | 소규모 내부 협업 사용자 | 공개 가입/회사 내부 전용인지 |
| Home 일정 범위 | 전체 공유와 나와 관련 구분, 범위 이름을 노출 | 관련 없는 공유 일정 수/실제 사용량 |
| 개인 task 담당 | 자신만 | 협업 할 일 수요는 추후 |
| deadline | 날짜 단위 우선, 설정 timezone에서 '오늘' | 정확한 시각 마감 필요 여부 |
| 공개 연락처 | 표시명/username/내부주소 최소 | 계정 목록 공개·전체 가입 사용자 의미 |
| 요청 역할 | 요청자와 명시된 담당자만 상태 행동 | 담당 수락·취소·종료 권한 |
| 장소 | 수요 확인 전 보류 | 개인/공유 주소·지도 비용 |
| 사용자 조직/role | 현재 없음, 임의 생성 금지 | 조직별 공간이 필요한지 |
| 개인화 | 기본 홈 안정화 후 정해진 카드 선택 | 초기 사용자에게 필요한 카드 |
| 실시간 표시 | refresh/제한된 visible 재조회로 시작 | 서버 부하·수신 push의 필요 |
| UI 언어/브랜딩 | 서비스 역할을 먼저 정함 | 한국어/영문/다국어 운영 |

기능 기획은 위 결정을 문서화한 것이며 지금 API/model/메뉴를 만들거나 데이터를 변경하지 않았다. 실제 구현의 권한·저장·성능 검토는 선택 범위를 개발할 때 수행한다.
