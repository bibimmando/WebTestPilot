# Dashboard 서비스 경험 개선안
기준일: 2026-10-10 · 서비스 중심 재검토본 · 기획만 완료, 구현 미착수

## 서비스의 첫 화면이 해야 할 일

현재 프로젝트는 개인 할 일·메일과 공유 일정·대화를 함께 쓰는 소규모 내부 협업 공간에 가깝다. 조직/프로젝트/운영자 권한 모델은 아직 없으므로 이를 완성된 조직 관리 서비스로 가정하지 않는다. 홈은 '오늘 무엇을 확인하고 처리해야 하는가'에 답하고 해당 작업으로 바로 이동하는 공간을 권장한다.

이번 재검토는 이전18개 화면 탐색과 현재 source를 사용했다. 로그인·API 호출·DB 접근 쿼리·추가 브라우저 탐색 없이 읽기와 Markdown 편집만 했다. 이전 테스트 중심 제안은 [보관본](ARCHIVED_TEST_ORIENTED_PLANNING.md), 이전 관찰은 [탐색 기록](01_SITE_EXPLORATION.md)이다. 아래 모든 변경은 계획이다.

## 현재 정보의 유지·개선·이동·제거

| 현재 요소 | 결정 | 이유·예상 동작 |
|---|---|---|
| 계정 이름·현재 날짜 | 유지/보강 | 현재 계정과 시간대가 분명해야 함. 계정 이름 클릭→기존 전환/내 설정 메뉴 |
| Saved events 총수 | 홈 주요 KPI에서 교체 | 누적 일정 수보다 오늘 일정/미완료 업무/미읽음이 더 행동 가능. 총수는 Calendar/리포트 보조 정보 |
| 오늘·다가오는 일정 | 유지/정리 | 다음 일정과 시간·장소·공유 범위 표시. 클릭→그 일정 상세; 상세에서 기존 수정/RSVP |
| Todo list | 유지/축소 | 기존 추가/완료 가능. 홈에는 중요한 일부와 전체 보기; 실제 전체 관리/마감은 W03 |
| unread Chat | 유지 | 수치 클릭→미읽음 방 중심 목록. 실제 메시지 읽기는 기존 Chat에서 |
| unread Email | 상단 요약으로 승격 | 현재 Account activity 문장 링크보다 눈에 띄는 카드. 클릭→자기 Inbox의 미읽음 필터 |
| 최근 메일 제목 | 추가 | 현재 홈은 unread 수치만 있음. 제목/발신자/시각→같은 reader; 미리보기로 자동 읽음 변경하지 않음 |
| Quick chat | 최근 대화로 명칭 정리 | 현재는 실제 방 미리보기이며 작성기가 아님. 해당 방으로 바로 이동 |
| Recent activity | 보조 영역으로 축소 | 현재 최신 자료 조합이지 전체 기록이 아님. 업무를 실행할 내용보다 아래에 배치 |
| Last7days activity chart | 리포트로 이동/작은 요약 | 홈의 첫 스크롤을 차지하지 않게. 지금 지표는 생성/발신 수이며 업무 성과로 표현하지 않음 |
| Sales report/Site visits/Weather | 정상 홈에서 제거, 개발 자료로 이동 | 실제 원장·방문·날씨 원천이 없고 협업 목적과도 직접 연결되지 않음. 날씨가 필요하면 별도 요구 확인 |
| New report·JSON Export | 리포트/상세 도구로 이동 | 현재 결과는 JSON 요약. 신규 업무보고 제출 기능으로 오인하지 않게. 홈 주 액션은 일정/메일/할 일 작성 |
| 'Check all sales'로 workspace report 열기 | 제거/올바른 명칭 | 매출 없는 화면의 잘못된 이동 기대를 없앰 |
| 무조건적인 빈 숫자0 | 개선 | 진짜0·로딩·조회 실패 구분. 실패에는 기존 표시 유지+다시 불러오기 |
| Mock 메일/샘플 안내 | 일반 업무에서 분리 | 업무 모드는 내부 Email/실제 Chat, Mock은 개발 자료 진입에서 명시적으로 선택 |

메뉴 개편과 더불어 기존 테마/색상·카드 전체를 유지해야 한다는 제한은 없다. 단순한 정보 구조와 모바일 우선 순위를 먼저 정하고 디자인은 그 구조에 맞춰 조정한다.

## 추천 레이아웃 A: 오늘의 업무 홈

```text
┌ Sidebar ──────┬─────────────────────────────────────────────────┐
│ 업무          │ 현재 계정 ▼   검색                       새로 만들기 ▼│
│ 홈            ├─────────────────────────────────────────────────┤
│ 할 일         │ 안녕하세요, 이름 · 오늘 날짜/시간대   마지막 갱신 ↻│
│ 일정          ├────────────┬────────────┬────────────┬────────────┤
│ 리포트*       │ 오늘 일정  │ 미완료 할 일│ 미읽음 메일│ 미읽음 채팅 │
│               │ 일정으로 → │ 할 일로 →  │ 받은편지함→│ 대화로 →   │
│ 협업          ├─────────────────────────┬───────────────────────┤
│ 메일          │ 오늘/다음 일정          │ 처리할 할 일           │
│ 채팅          │ 시각 · 제목 · 장소       │ 제목 · 마감* · 중요도*  │
│ 구성원*       │ [일정 추가] [전체 보기]  │ [빠른 추가] [전체 보기] │
│               ├─────────────────────────┼───────────────────────┤
│ 요청/장소**   │ 최근 받은 메일          │ 최근/즐겨찾는 대화      │
│               │ 발신자 · 제목 · 시각     │ 방 이름 · 미읽음 · 최신 │
│ 계정/도움말   ├─────────────────────────┴───────────────────────┤
│               │ 확인할 항목* → 이후 개인 리포트 요약/최근 활동   │
└───────────────┴─────────────────────────────────────────────────┘
* 해당 후속 기능 구현 후 표시. ** 사용 목적과 범위 승인 시만 추가.
```

첫 버전의 할 일은 현재 미완료 목록이며 마감 임박/중요도는 데이터가 생긴 뒤 표시한다. 일정에 '나와 관련' 필터를 적용할 경우 서버의 잘린 upcoming 목록을 프런트에서만 걸러 중요한 항목을 누락시키지 않도록 조회 범위를 같이 설계한다.

모바일은 계정/검색 → 네 요약2×2 → 오늘 일정 → 할 일 → 메일 → 대화 순서다. 긴 원문 대신 제목/시각을 보여 주고 하나의 상세 화면으로 이동한다. 추가 버튼은 메뉴 하나로 묶고 클릭 영역/툴팁이 화면 밖으로 넘치지 않게 한다.

## 대안 B: 나의 업무와 공유 소식 분리

상단 탭 '나의 업무 / 공유 소식'으로 개인 할 일·메일·초대 일정과 전체 공유 일정·방 활동을 분리할 수 있다. 전체 공유 방/일정이 많아지는 경우에 적합하다. 그러나 현재 조직별 공간 모델이 없어 '나의 팀'이나 '프로젝트별' 탭으로 이름 붙이지 않는다.

A는 주요 기능을 한눈에 보고 도입이 빠르다. B는 공유 정보가 많은 환경에 유리하지만 탭 밖 소식을 놓칠 수 있다. **A를 기본으로 시작하고 공유 정보량이 실제로 증가할 때 B를 검토**한다. 최초부터 자유 canvas 위젯 편집을 요구하지 않고 W15는 후속 개인화로 둔다.

## 핵심 제안

### W01. 오늘의 업무 홈

**현재 상태:** 오늘/다가오는 일정, 개인 할 일, 미읽음 채팅·메일, 최근 활동이 이미 있다. 카드가 샘플 판매·날씨·방문과 섞이고 클릭은 대체로 각 페이지의 첫 화면으로 이동한다.

**추가·개선할 기능:** 오늘의 일정과 내가 처리할 일을 먼저 배치하고 일정·할 일·메일·대화를 해당 항목으로 바로 연결한다. 상단 네 지표는 오늘 일정/미완료 할 일/미읽음 메일/미읽음 채팅으로 정리한다. 처음에는 기존 데이터를 사용하고 마감·중요도 분류는 W03 이후 추가한다.

**필요한 이유:** 로그인 직후 무엇을 해야 하는지 알 수 있고, 수치 확인 뒤 필요한 화면을 다시 찾는 시간을 줄인다.

**사용 시나리오:** 아침 로그인 → 다음 일정 확인 → 관련 일정 상세 → 미읽음 메일 열기 → 미완료 할 일 처리 → 홈으로 돌아와 갱신된 상태 확인.

**예상 화면 구성·클릭 동작:** 상단 현재 계정·날짜·새 작업 버튼, 그 아래 클릭 가능한4개 요약, 중앙 오늘 일정과 할 일, 하단 최근 메일/대화. 일정 클릭은 해당 일정 상세, 할 일은 목록의 선택 항목, 메일은 해당 reader, 채팅은 해당 방으로 이동한다.

**기존 기능과의 연계:** 기존 /api/dashboard, Calendar, tasks, Email, Chat을 요약한다. 작성·답장은 기존 화면에 맡긴다. 현재 데이터는 '전체 공유/나와 관련' 구분을 추가해야 하며 마감일을 추정하지 않는다.

**구현 난이도:** Medium. dashboard.js/index.html 및 집계 범위·deeplink 보강. 새 업무 원장 없이 시작한다. 최근 Inbox 제목 요약을 추가하는 경우 owner 범위 조회가 필요하다.

**선행 조건·미결정 사항:** W02의 항목 이동 계약. 마감 임박 표현은 W03 이후; 개인 일정 범위 조회는 W09와 공유.

**기존 기능과의 차이:** 새 일정/채팅/메일/할 일 기능의 재구현이 아니라 기존 데이터를 중심으로 한 화면 재배치·이동 개선.

**우선순위:** High · 서비스 가치 94/100 · 권장 단계 1.

### W02. 항목 바로가기와 맥락을 잇는 빠른 실행

**현재 상태:** Dashboard의 일정/대화 링크는 대부분 calendar.html/chat.html로 이동한다. 메일 작성 모달과 Calendar 생성·Chat private 방은 이미 구현되어 있다.

**추가·개선할 기능:** URL 또는 공통 navigation 상태로 eventId/roomId/mailId/taskId와 복귀 위치를 전달한다. '새로 만들기' 메뉴는 일정·메일·할 일을 기존 작성 화면에 열고, 선택한 구성원에게 메일/대화를 시작할 수 있게 한다.

**필요한 이유:** 기능은 있는데 관련 화면과 항목을 다시 찾게 만드는 단절을 해결한다.

**사용 시나리오:** 홈에서 메일 제목 클릭 → 같은 메일 reader → 뒤로가기 시 홈 위치 유지. 구성원 카드에서 채팅 클릭 → 기존 private1:1 방 열기.

**예상 화면 구성·클릭 동작:** 헤더에 '새로 만들기' 드롭다운, 카드별 '전체 보기', 행별 실제 상세 링크, 상세 상단 뒤로가기. 모바일은 한 개의 추가 메뉴로 묶는다.

**기존 기능과의 연계:** 기존 compose modal/독립 compose 페이지, Calendar modal, private pair 방 생성, NAV와 command palette를 재사용한다.

**구현 난이도:** Medium. 각 페이지 controller의 initial query 처리와 공통 navigation helper 예상. ID만 넘겨도 서버 접근 검사를 다시 수행한다. 새 통신 API를 만들 필요는 없다.

**선행 조건·미결정 사항:** 각 화면의 id 조회·선택·복귀 계약. Tasks 상세는 W03 이후, 존재하지 않는 링크는 안전한 안내로 처리.

**기존 기능과의 차이:** 이미 있는 작성·private 채팅 생성 기능에 진입 경로만 추가하며 자동 발신/자동 일정 생성은 하지 않는다.

**우선순위:** High · 서비스 가치 97/100 · 권장 단계 1.

### W03. 개인 할 일 전용 페이지와 마감 관리

**현재 상태:** Dashboard에서 개인 task 추가·완료·삭제가 저장된다. Task는 id/title/done 수준이며 전용 페이지·마감일·우선순위·상세 수정은 없다.

**추가·개선할 기능:** 동일한 개인 할 일을 전용 페이지에서 모두 관리한다. 제목 수정·설명·마감일·중요도·완료 시각·오늘/예정/마감 지남/완료 필터를 추가하고 홈에는 처리할 일부만 보여 준다.

**필요한 이유:** 업무를 지속적으로 정리할 중심 기능이 Dashboard의 작은 목록에 갇혀 있다. 날짜와 중요도가 있어야 홈의 우선순위도 의미를 갖는다.

**사용 시나리오:** 메일로 받은 업무를 할 일로 입력 → 금요일 마감 지정 → Tasks에서 마감순 확인 → 완료 → 홈과 완료 목록에 함께 반영.

**예상 화면 구성·클릭 동작:** Sidebar '할 일', 상단 검색·추가, 좌측 또는 상단 필터, 중앙 목록, 우측 상세 편집. 모바일은 상세를 별도 패널로 열고 한 번에 한 작업을 편집한다.

**기존 기능과의 연계:** 기존 private Workspace tasks 데이터가 원본이다. 홈의 빠른 추가·완료와 동일 상태를 사용한다. W04는 이 할 일에 원본 연결을 붙인다.

**구현 난이도:** High. backend/workspace.py 엄격 Task 검증과 store/controller 변경이 필요하다. 분리된 Task 모델 채택 시 원본 id/title/done을 비파괴 이전한다. 지금 스키마/원본을 변경하지 않는다.

**선행 조건·미결정 사항:** 기존 snapshot 포맷 확장/리소스 전환 중 하나를 먼저 결정. deadline의 날짜/시간대·완료 기록 규칙 필요.

**기존 기능과의 차이:** 할 일 자체는 신규가 아니며 기존 기능의 전용 화면·정보 확장이다. 초기에는 개인용; 협업 담당자·프로젝트 보드는 제외.

**우선순위:** High · 서비스 가치 91/100 · 권장 단계 2.

### W04. 메일·일정·대화에서 후속 할 일 만들기

**현재 상태:** 각 기능은 독립 저장·조회되며 task에 원본 참조가 없다. 메일 답장·일정 CRUD·메시지 송수신은 이미 있다.

**추가·개선할 기능:** 상세 메뉴의 '할 일로 추가'가 제목·마감일을 검토하는 작은 창을 열고 sourceType/sourceId를 붙인다. 할 일 상세에서 원본으로 돌아갈 수 있으며 같은 원본에서 만든 내 할 일이 있으면 먼저 보여 준다.

**필요한 이유:** 소통에서 나온 약속을 개인 업무로 옮겨 적고 원본을 다시 찾는 과정을 줄인다.

**사용 시나리오:** 메일의 자료 요청 → 할 일로 추가 → 제목/마감 확인 → Tasks에 저장 → 다음 날 '원본 메일 보기'로 요청 내용을 확인.

**예상 화면 구성·클릭 동작:** 메일 reader·일정 상세·메시지 메뉴의 한 액션, 확인 dialog, task 상세의 원본 chip. 원본 전체 본문은 task에 복사하지 않는다.

**기존 기능과의 연계:** W03 Task와 기존 mail/event/message ID를 연결한다. 원본의 읽음·답장·수정 권한은 기존 규칙을 따른다.

**구현 난이도:** High. task source reference 저장·자기 task 생성 API/검증 예상. 원본 변경·삭제 시 task 자체는 남고 '원본 사용 불가' 표시. 공유 방 메시지에서도 만들어진 task는 개인용이다.

**선행 조건·미결정 사항:** W02·W03, 타입별 접근 검사와 원본 삭제/권한 변경 정책.

**기존 기능과의 차이:** 프로젝트나 메시지 복사본을 새로 만드는 기능이 아니라 개인 업무의 원본 링크.

**우선순위:** High · 서비스 가치 86/100 · 권장 단계 3.

### W07. 확인이 필요한 항목을 모은 알림함

**현재 상태:** 상단 Notifications는 일정 목록/수이며 독립 알림함이 아니다. Email/Chat 미읽음과 일정 RSVP 정보는 있다. 실제 mention/알림 read/dismiss 원장은 없다.

**추가·개선할 기능:** 초대 응답 대기·마감 임박 내 할 일·미읽음 메일/대화의 요약을 한 곳에 묶고 종류별로 원본 화면에 연결한다. 첫 단계는 원본 상태에서 계산하는 '확인할 항목'이며 별도 읽음/삭제 알림 원장은 만들지 않는다.

**필요한 이유:** 단순 일정 개수보다 지금 확인·응답해야 할 일을 알리는 것이 사용자에게 유용하다.

**사용 시나리오:** 헤더 배지 확인 → 초대 대기 항목 선택 → Calendar에서 수락 → 알림함 새로고침으로 해당 항목 사라짐.

**예상 화면 구성·클릭 동작:** 헤더 popover에 확인 필요/메시지 탭, 종류·시각·짧은 설명·모두 보기. 홈에는 요약3개. Chat은 방별로 묶어 메시지마다 중복 표시하지 않는다.

**기존 기능과의 연계:** RSVP·unread·W03 deadline을 원본으로 계산한다. 읽음/완료/응답 동작은 원본 화면에 위임한다.

**구현 난이도:** Medium. 대기항목 조회 집계 예상; 원본이 알림 사유를 결정한다. 기존 Notifications badge의 '전체 일정 수'와 의미 변경을 명시.

**선행 조건·미결정 사항:** W02·W03 및 항목 우선순위/갱신 정책. mention이나 push·일괄 알림 읽음은 별도 후속.

**기존 기능과의 차이:** 일정/메일 복제본이나 또 다른 업무 목록이 아니라 처리 필요 항목을 찾는 뷰.

**우선순위:** Medium · 서비스 가치 80/100 · 권장 단계 3.

### W15. 홈 카드·즐겨찾기 개인화

**현재 상태:** Blank는 Duplicate/Add section 무동작 레이아웃이다. 테마 설정은 있지만 계정별 홈 구성/즐겨찾기는 없다.

**추가·개선할 기능:** 사용자가 홈 카드 순서/숨김과 즐겨찾는 내부 화면을 저장한다. Blank를 별도 메뉴 대신 '홈 편집' 진입점으로 활용하고 기본 구성 복원을 제공한다.

**필요한 이유:** 메일을 자주 쓰는 사람과 일정 위주인 사람이 각자 필요한 내용을 먼저 볼 수 있다.

**사용 시나리오:** 홈 편집 → 메일 카드 위로 이동 → 리포트 숨김 → 즐겨찾는 채팅방 추가 → 저장 → 다음 로그인에도 같은 구성.

**예상 화면 구성·클릭 동작:** 홈의 '화면 설정', 카드 표시 checkbox·위/아래 이동·미리보기·기본값 복원. 모바일 순서도 동일 정책; 자유 HTML 편집 없음.

**기존 기능과의 연계:** W01 카드 renderer·W05 preference 저장·W10 방 즐겨찾기. 한 곳에서 같은 preference를 관리한다.

**구현 난이도:** Medium. 개인 preference의 widget enum/order/visibility·정해진 resource favorite 예상. 임의 URL이나 HTML을 저장하지 않는다.

**선행 조건·미결정 사항:** 기본 홈 구조 안정화, 계정 preference 모델, 접근 불가 즐겨찾기 처리.

**기존 기능과의 차이:** 새 canvas 도구가 아닌 기존 Home의 개인화. 업무 모델을 복제하지 않는다.

**우선순위:** Low · 서비스 가치 66/100 · 권장 단계 3.


## 홈에서 이어지는 하루

오전 홈에서 약속을 확인하고 Calendar의 기존 상세에서 참석 응답한다. 최근 메일을 열어 요청을 읽고 W04로 개인 할 일을 만든다. 관련 구성원과 기존 private Chat에서 논의한다. Task를 완료하면 홈의 미완료 수가 줄고 기록된 완료 시각은 리포트에 반영된다. 다른 계정으로 전환하면 공유 자료는 정책대로 계속 보이지만 메일/할 일/개인 설정은 새 활성 계정 기준으로 바뀐다.

처음부터 모든 메시지를 홈에서 답장하거나 일정을 inline 편집하지 않는다. 홈은 확인/빠른 진입, 원래 페이지는 해당 업무의 작성·처리 책임을 갖는다.

## 진행 판단과 부가 검증

우선 판단은 사용자가 필요한 작업을 빨리 찾는지, 소통 결과를 업무로 이어갈 수 있는지, 자신의 정보와 공유 정보가 구분되는지다. 실제 구현 시 확인할 기본 품질은 항목 이동·저장/갱신·권한·모바일 접근성이며 테스트 자동화는 이 사용자 경험을 확인하는 보조 수단이다. 버그 인젝션을 위한 화면/모델은 제안하지 않는다.
