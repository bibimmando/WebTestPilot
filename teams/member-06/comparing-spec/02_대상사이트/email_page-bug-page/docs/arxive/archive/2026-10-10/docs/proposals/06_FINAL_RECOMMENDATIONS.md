# 서비스 경험 중심 최종 권고
기준일: 2026-10-10 · 이전 테스트 중심 결론 대체 · 제안16개 모두 미구현

## 권장 서비스 성격

Adminator를 **개인 업무와 공유 소통을 연결하는 내부 협업 공간**으로 발전시키는 것을 권장한다. 현재 개인 tasks·내부 Email·공유/개인 Calendar·shared/private Chat·다중 계정 인증이 있어 이 방향과 잘 맞는다. 조직·프로젝트·운영자 권한이 완성된 서비스는 아직 아니다. CRM/ERP/매출/방문 분석을 template의 그림만 보고 도입하지 않는다.

홈은 오늘 확인·처리할 것을 보여 주고, Sidebar는 사용자의 업무 목적대로 이름 붙인다. UI samples는 개발 자료로 보존할 수 있으나 일반 업무 메뉴에서 분리한다. 실제 기능에 필요한 모달·버튼·표는 공용 컴포넌트로 사용한다. 이번 우선순위에서 자동화 테스트/버그 인젝션의 가중치는0이며 부가 품질 확인으로만 다룬다.

## Dashboard의 선택

'오늘의 업무 홈'을 기본으로 추천한다. 상단 현재 계정·날짜·빠른 실행,4개 실제 요약, 중앙 일정·개인 할 일, 하단 최근 Inbox·최근 방 순이다. 판매/방문/날씨 샘플은 홈에서 빼고 현재 JSON report/차트는 리포트의 도구/보조 정보로 옮긴다. 새로고침·실패 표시·전체 보기·항목 직접 이동을 제공한다.

마감/중요도는 W03 데이터가 생긴 뒤 표시하며 현재 Task에 마감이 있다고 가정하지 않는다. 전체 공유 정보가 많아지면 '나의 업무/공유 소식' 두 탭 대안을 검토한다. 텍스트 와이어프레임은 Dashboard 문서에 있다.

## Sidebar의 선택

업무: 홈·할 일·일정·리포트. 협업: 메일·채팅·구성원. 계정: 헤더의 내 프로필·환경설정·기존 계정 전환·로그아웃. 신규 메뉴는 실제 기능이 준비되면 노출한다. 요청/장소는 수요가 확인될 때만 추가한다.

Forms는 자기 설정/요청 작성에, Tables는 실제 목록/리포트에 사용한다. Basic Table을 별도 일정 CRUD로 바꾸지 않고 이미 있는 Calendar Agenda에 합친다. UI Elements/Buttons는 공용 UX·개발 자료, Blank는 홈 편집 진입으로 이동한다.404/500/로그인/가입은 상황별 화면으로 처리한다. 각 현재 페이지20개 항목의 대응표는 Sidebar 문서에 있다.

## 서비스 전체가 연결되는 사용 흐름

홈에서 일정을 확인하고 해당 상세에서 RSVP한다. 메일로 받은 업무를 W04로 개인 할 일에 연결하고 구성원에게 기존 private Chat으로 문의한다. 완료한 일은 홈과 Task 목록에 함께 반영되고 기록된 기간부터 업무 리포트에 나타난다. 검색은 자료를 찾고 대기함은 확인해야 할 원본을 안내한다. 다른 계정으로 전환하면 공유 정책은 유지되지만 메일/Tasks/개인 preference는 활성 계정 기준으로 바뀐다.

원본 내용을 여러 저장소에 복사하거나 task/요청/알림을 같은 객체로 섞지 않는다. Task는 내가 해야 할 일, 요청은 요청자/담당자가 주고받는 처리 과정, 대기함은 기존 원본 상태의 확인 뷰다.

## 이번에 채택하지 않는 방향

실습 wizard·실습 레코드·버튼 작업대·원하는 오류를 만드는 테스트 페이지를 제품의 우선 기능으로 만들지 않는다. Maps 두 종류를 유지하기 위해 실제 지점 없는 지역 분석을 만들지 않는다. 실제 User 역할·온라인 상태·매출·오류 신고 완료가 없는 상태에서 그런 정보를 표시하지 않는다. 외부 메일/첨부·운영자 권한·공유 범위 변경은 별도 요구로 남긴다.

독립 신규 기능 중 가장 자연스러운 것은 구성원 연락처다. 일반 업무 요청은 의미 있는 후보지만 실제 처리 수요와 담당자 규칙이 확인되지 않아 후순위다. 장소 역시 오프라인 일정 수요가 없다면 보류한다.
