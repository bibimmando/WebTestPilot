# 비교 검토에서 재사용할 판단 노하우

## 먼저 고정할 것

비교 단위는 보고서 건수, 고유 명세 ID, 증상, 근본 원인 중 무엇인지 명시한다. 주입 결함 명세를 평가한다면 명세 ID가 유용하지만 모든 비교가 같은 단위를 갖지는 않는다. 유사 ID를 가진 다른 제품 문서나 과거 목록을 현재 정답으로 합치지 않는다.

집계 전에 포함할 보고서 범위와 부분 일치의 취급을 정한다. 결과를 본 뒤 유리한 기준을 선택하지 않는다. 사용자의 기준이 명확하면 따른다. 모호함이 결과를 바꾸면 선택한 기준과 대안을 설명한다. 본문/부록을 항상 두 지표로 나누거나 모든 부분 관찰을 항상 인정/제외하는 규칙은 두지 않는다.

## 주장과 증거를 연결하는 법

- 보고서 이슈는 포장 단위다. 독립된 주장은 나누어 평가하되 원래 묶음과 위치를 유지한다.
- 다른 경로·페이지에서 같은 공통 원인이 드러나면 중복일 수 있다. 반대로 같은 화면·조작에서 나타나도 서로 다른 명세 조건이면 따로 대응할 수 있다.
- 실행 완료, 요청 수락, 데이터 저장, 사용자에게 보인 성공, 실제 업무 결과는 같은 사건이 아니다. 주장한 결과까지 근거가 이어지는지 본다.
- 증상의 일부만 맞으면 확인한 하위 조건과 못 본 조건을 쓴다. 검토자가 추가로 확인한 결과와 원 도구가 당시 관찰한 결과를 분리한다.
- 과거 보고서와 현재 구현이 다르면 현재 재현 실패만으로 과거 보고서를 오탐으로 확정하지 않는다. 반대 방향도 마찬가지다.
- 명세가 모든 실제 문제를 열거한다고 가정하지 않는다. 명세 밖 사실을 기록하되 고정 분모의 성적을 사후에 바꾸지 않는다.

## 꼭 구분할 혼동

| 겉으로 보인 것 | 구분할 대안 | 구분에 유용한 관찰 |
|---|---|---|
| 변화가 없음 | 이미 목표 상태 / 차단 정책 / 잘못된 대상 / 실제 무반응 | 시작 상태와 대상, 실행 결과, 상태 변화의 범위 |
| 강조·흐림·가림 | 선택 상태 / hover·focus / 로딩·애니메이션 / 지속 결함 | 입력·시간 조건을 바꾼 최소 대조와 안정된 화면 |
| 항목이 안 보임 | 삭제 / 잘림 / 내부 스크롤 / 접힘 / 가상 목록 | 실제 접근 가능성, 경계·스크롤·동작 결과 |
| 같은 정보가 두 번 보임 | 중복 업무 처리 / 서로 다른 사본 / 표시 중복 | 식별자·소유자·상태·요청 수와 UI의 대응 |
| 입력 오류가 안 나옴 | 검사 누락 / 앞선 오류가 검사 차단 / 다른 입력 경로의 규칙 | 실패 순서와 비교 가능한 정상 경로 |
| 오류·거절 응답 | 제품 결함 / 의도된 검증 / 인증 만료 / 테스트 정책 | 원래 기대, 요청 조건, 제한을 해제한 대조의 허가 범위 |

이 표는 진단 후보이지 사이트에 반드시 존재하는 버그 목록이 아니다. 모든 항목을 무조건 실험하지 않는다.

## 작은 대조 실험의 설계

주장을 가르는 불확실성 하나에 집중한다. 가능한 한 다른 조건은 유지하고, 관찰/스크립트/시각 변조 여부를 기록한다. 강제 클릭, CSS 수정, 합성 이벤트, 응답 대체로 만든 결과를 정상 사용자 재현과 같은 것으로 취급하지 않는다. 기존 테스트의 과거 PASS는 이번 실행 증거가 아니다.

제공 자료만으로 충분하면 새 서버나 브라우저를 띄울 필요가 없다. 실행할 때는 기존 사용자 DB와 세션을 보존하고, 생성한 서버·데이터·산출물을 구분한다. 원 도구 전체를 다시 돌리는 것은 비교 검토와 다른 작업이다.

## 추가 항목을 남기는 문장 구조

“이 조건에서 이 사실을 관찰했다. 이 기대는 이 자료에 근거한다. 이 대안 설명은 이 근거로 배제/유지했다. 따라서 확인된 결함/후보/환경 영향/개선 제안으로 분류한다. 독자는 이 절차로 재확인할 수 있다.”

문서 제목이나 개발자 주석만으로 실제 동작을 확정하지 않는다. 기술 규약의 적용 대상·예외와 제품 고유 요구를 구분한다. 증상 관찰이 확실하더라도 기대가 불명확하면 판정은 미확정일 수 있다.

## 마지막 대조

합계와 표의 고유 항목 수가 같은지, 중복 제거가 양쪽 보고서에 일관되는지, 미실행을 누락/정상으로 잘못 바꾸지 않았는지 확인한다. 시간·권한·데이터·범위가 다르면 단일 성적의 의미를 제한한다. 보고서를 완성한 뒤 중요한 그림과 실제 상태를 다시 보았을 때 설명이 달라지면 기록과 본문을 함께 갱신한다.


## 의도된 버그와 추가 버그의 두 집계

사용자가 두 범위를 비교하려는 경우 다음 계산을 병기한다. 아래 명칭은 주입 결함 비교의 예이며 다른 과제에서는 사용자가 지정한 정답 목록의 이름을 쓴다.

| 계산 대상 | 계산식 |
|---|---|
| 의도된 버그만 | 발견한 의도된 버그 수 / 전체 의도된 버그 수 × 100 |
| 확인된 추가 버그 포함 | (발견한 의도된 버그 수 + 해당 도구가 발견한 추가 버그 수) / (전체 의도된 버그 수 + 비교 대상 보고서에서 확인된 고유 추가 버그 수) × 100 |

두 번째 분모의 추가 버그는 보고서별 개수를 더한 값이 아니라 확인된 고유 항목의 합집합이다. 모든 도구에 같은 분모를 적용하고, 분자에는 해당 도구가 기록한 항목만 넣는다. 검토자가 단독으로 새로 찾은 문제를 도구 실적으로 돌리지 않는다. 합집합은 이번 비교에서 확인한 집합이며 사이트의 모든 실제 결함을 완전히 열거한 정답이 아니다. 미확정 후보·환경 영향·개선 제안은 확정 추가 버그 분모에 넣지 않는다. 추가 버그가 없는 경우와 확인 자료가 없어 개수를 모르는 경우를 구분한다. 분모가 0이면 비율은 계산 불가로 표기한다.

숫자가 대입된 계산표와 간단한 수식을 함께 제공한다. 추가 버그의 내용·영향을 별도 절에서 설명하는 것과 두 번째 비율을 계산하는 것은 양립한다. 보고서의 제목 개수, 본문/메모 구분을 이 두 집계와 혼동하지 않는다. 부분 증상을 인정한 경우 무엇까지 기록됐는지 표시하고 확인 깊이가 동일하다고 해석하지 않는다.

## 기존 기록과 개정본 대조

이전 초안을 정답으로 간주하지 말고 원본 보고서·명세·코드·보존된 실험 기록으로 돌아가 대조한다. 원본 해시나 버전을 확인할 수 있으면 변경 여부를 기록한다. 집계 항목의 고유 ID, 도구별 출처, 수식, 표와 차트 수치, 페이지 참조, 실험 조건을 맞춰 본다. 특히 오류 문구·입력 경로·조작 종류가 다른 관찰을 하나의 확정 결과로 확대하지 않는다.

기존 증거의 관찰 사실은 보존한다. 사용자의 기준 변경으로 집계가 달라진 경우 사실 수정과 집계 기준 변경을 구분해 새 기록에 남긴다. 최신 문서와 연결된 검수 기록도 갱신하여 이전 분모나 PDF 페이지 수가 최신 결과처럼 읽히지 않게 한다. 자료 대조만으로 충분하면 사이트를 다시 실행하지 않는다.
