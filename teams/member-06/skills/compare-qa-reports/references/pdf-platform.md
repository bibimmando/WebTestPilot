# 공통 PDF 제작 플랫폼

## 역할 분리

검토자가 `review-ledger.template.json`에 근거와 집계 기준을 기록하고 문서 JSON에 표현할 내용을 넣는다. `render_report.py`는 표현만 담당한다. 특정 보고서 구조·사이트·버그 ID·도구 이름·정답 개수·점수를 포함하지 않는다. 내용이 같아야만 작동하는 전용 생성기를 만들지 않는다.

PDF가 필요할 때만 의존성을 설치한다. 환경에 번들 문서 런타임이 있으면 우선 사용한다.

```sh
python -m pip install -r requirements-pdf.txt
python scripts/render_report.py --input document.json --out comparison.pdf
```

기존 출력은 기본적으로 덮어쓰지 않는다. 내용을 고친 뒤 재생성할 때 `--overwrite`를 지정한다. 폰트를 자동으로 찾지 못하면 `--font /path/regular.ttf --bold-font /path/bold.ttf`로 지정한다. 한글을 지원하는 글꼴을 사용한다. 글꼴 파일 자체는 이 스킬에 포함하지 않는다.

## 문서 JSON 계약

루트 `format`은 `qa-comparison-document/1`, `title`은 필수다. `subtitle`, `footer`, `metadata`는 선택이다. `metadata`는 두 문자열의 배열 목록이고 `metadata_headers`로 두 열의 이름을 바꿀 수 있다. `sections`에는 `title`, 선택 `new_page`(기본 false), `blocks`를 넣는다. 페이지 수를 미리 고정하지 않아도 된다.

지원 블록:

| type | 필드 | 용도 |
|---|---|---|
| paragraph | text | 일반 본문. HTML을 실행하지 않고 텍스트로 취급 |
| note | text | 보조 설명·한계·출처 |
| table | headers, rows, 선택 widths | 폭 비율로 표 생성. 머리말 반복, 긴 표 페이지 분할 |
| image | path, 선택 caption, max_height | 로컬 그림을 비율 유지해 배치. 경로는 문서 JSON 기준 |
| bars | rows | label, value, total을 제공한 행만 막대로 표시 |

숫자와 표 내용은 검토자가 제공한다. 막대는 value/total을 시각화하지만 total이 명세 분모인지, value가 정당한 발견인지 판단하지 않는다. 서로 다른 기준의 분모를 같은 비교처럼 배치하지 않았는지 검토자가 확인한다. title·caption·본문·표의 문자열에 마크업을 넣을 필요는 없다.

입력 검사로 필수 필드·표 열 개수·폭·숫자 범위·이미지 존재를 확인한다. 입력 구조 오류를 발견하면 PDF 작성 전에 멈춘다. `--out` 옆의 `.render.json`에는 입력/출력 SHA-256, 사용 폰트와 페이지 수를 기록한다. 원본 입력 자료나 비밀값을 자동 수집하지 않는다.

## 검토 메타데이터를 채울 때

빈 검토 기록의 배열에는 현재 작업에서 필요한 객체만 넣는다. `inputs`에는 역할·경로·해시·버전, `ground_truth`에는 단위 ID와 기대·근거를 기록할 수 있다. `reports`에는 실행 조건을, `claims`에는 원보고서 위치·원래 표현·대응 명세·관찰 범위·판정·근거를 넣는다. `additional_findings`에는 명세 밖 항목의 사실·기대·보류 이유·재확인 절차를 기록한다. `results`는 집계 기준이 정해지고 계산됐을 때만 채운다.

이 양식은 특정 데이터 스키마를 강제하는 검증기가 아니다. 꼭 필요할 때만 작업별 JSON Schema나 계산 도구를 추가한다. PDF 문서 JSON과 판단 기록은 목적이 다르므로 동일 파일로 합칠 필요도 없다.

## 시각 검수

생성 성공과 내용 정확성은 별개다. PDF를 PNG로 렌더링하고 실제 페이지를 확인한다. 사용 가능한 경우:

```sh
pdftoppm -scale-to 1400 -png comparison.pdf preview
```

표 머리말·행 분할, 글꼴 누락, 긴 경로/URL의 줄바꿈, 그림 확대 비율, 문장·숫자와 증거의 일치를 확인한다. 내용 수정 뒤 영향받은 페이지를 다시 렌더링한다. 렌더러가 지원하지 않는 복잡한 배치가 필요한 경우에만 해당 부분을 확장하며, 단일 사이트의 레이아웃을 공통 플랫폼 규칙으로 굳히지 않는다.


## 독자용 보고서와 개정본

첫 장은 도구별 비교 결과, 해당 숫자가 대입된 표, 간단한 수식과 필수 약자 설명을 중심으로 만든다. 의도된 버그만/확인된 추가 버그 포함을 요청했다면 두 행을 나란히 두고 각 분모가 무엇인지 적는다. 계산 근거를 내부 기록 용어로 대신하지 않는다. 원래 ID는 설명과 함께 쓰고 출처는 도구 이름과 페이지로 쓴다.

이후에는 버그별 발견·미발견 비교, 도구별 확인 범위, 추가 버그의 영향·근거·재확인 방법, 확정하지 않은 주장과 실행 조건 차이를 독자가 따라갈 수 있게 배치한다. 절 순서나 페이지 수는 자료에 맞춘다.

시각자료는 판단에 도움이 되는 곳에 사용한다. 비율은 공통 분모가 드러나는 막대, 발견 범위는 비교표, 화면 결함은 실제 스크린샷을 활용할 수 있다. 캡션에는 무엇을 보여주는지와 도구의 원래 증거인지 검토자가 재현한 화면인지 적는다. 단순 장식이나 실제 관찰처럼 보이는 합성 증거는 넣지 않는다. 표·본문·차트의 숫자와 확인 한계를 맞춘다.

개정본은 파일명과 표지의 버전 또는 날짜로 구별한다. 같은 파일명 덮어쓰기로 이전 미리보기와 혼동될 수 있으면 별도 경로로 전달한다. 현재 문서 JSON과 검수 기록을 연결하고, 과거 초안·실험 원자료를 최신 자료로 오인하지 않도록 표시한다. 전달 전에 변경한 페이지를 렌더링해 확인하고, 페이지 수가 바뀌면 문서 내 참조와 연결된 기록도 대조한다.
