# QA 보고서 비교·검증

명세와 실제 구현·동작을 기준으로 보고서들을 대조해 발견률과 주장별 타당성을 평가하고, 추가 문제의 근거와 재확인 방법을 남긴다. 특정 사이트·도구·버그 분류·숫자·언어를 기본 정답으로 가정하지 않는다.

## 비교 방법

- **기준부터 확인한다.** 어떤 자료가 정답 명세이고 어떤 자료가 약자 설명·과거 기록인지 구분한다. 이름이 비슷한 문서의 대상·버전이 다른지 확인한다. 사용자가 지정한 분모를 조용히 교체하지 않는다. 완전한 정답 목록이 없으면 전체 발견률을 만들어 내지 않는다.
- **보고서를 주장 단위로 읽는다.** 제목/요약뿐 아니라 관련 본문·부록·표·그림도 확인하되 정식 발견, 탐색 메모, 미실행, 자동화 실패를 구분한다. 페이지·절·원래 이슈 ID를 보존한다.
- **명세와 대응시킨다.** 하나의 이슈가 여러 독립 명세 항목을 포함할 수도, 여러 이슈가 한 결함을 반복할 수도 있다. 같은 현상이라는 이유만으로 합치거나 비슷한 제목이라는 이유로 다른 ID까지 인정하지 않는다. 부분 조건만 관찰된 경우 범위를 남긴다.
- **필요한 만큼 사실을 확인한다.** 제공된 실행 기록·화면·구현을 우선 대조한다. 여전히 불확실한 주장만 허가된 환경에서 최소한으로 확인한다. 현재 소스와 과거 실행 버전의 차이를 표시한다. 앱 전체 재탐색이나 반복적인 계획 수립을 자동으로 시작하지 않는다.
- **증상과 판정을 분리한다.** 관찰 사실, 제품 기대, 기술 규약, 검토자의 추론을 따로 쓴다. 타임아웃/선택자 실패는 곧 제품 결함이 아니다. 관찰됐어도 요구가 불분명한 항목은 보류할 수 있다. 섬세한 판단은 [비교 노하우](references/comparison-method.md)를 읽는다.
- **집계 기준을 드러낸다.** 사용자가 요청한 단위·분모·포함 범위·부분 일치·중복 처리로 계산한다. `발견한 고유 명세 결함 / 전체 명세 결함`을 accuracy/precision과 혼동하지 않는다. 보고서 내 기록 위치와 평가할 버그 집합은 서로 다른 기준이다. 사용자가 요청한 지표를 본문/부록 등 내부 기록 구분으로 대체하지 않는다. 부분 증상 인정 여부는 수치 옆에 설명한다. 이번 검토자가 보완한 증거를 원 도구가 확보한 증거로 소급하지 않는다.
- **추가 항목은 별도로 남긴다.** 명세 밖에서 실재한 문제, 제품 기대 확인이 필요한 후보, 환경 영향, 개선 제안을 구분한다. 의도된 버그만의 비율은 원래 분모를 유지한다. 추가 버그를 포함하는 비교도 요청되면, 두 보고서에서 확인한 고유 추가 버그의 합집합을 공통 분모에 더한 두 번째 비율을 함께 제시한다. 추가 버그를 별도로 설명한다는 이유로 이 계산을 생략하지 않는다. 구체적인 식과 포함 조건은 [비교 노하우](references/comparison-method.md)의 집계 절을 따른다.

## 남길 결과

보고서는 독자가 명세 → 원보고서 주장 → 확인 근거 → 집계 결과를 따라갈 수 있어야 한다. 수치를 해석하는 데 중요한 실행 권한·상태·시간·버전 차이를 함께 적는다. 하나의 사례로 도구 일반 성능을 순위화하지 않는다.

추가 항목에는 시작 상태·구체적 조작·기대/실제·반대 증거·확인 한계와 파일 위치를 남긴다. 사용자 재확인은 기존 데이터에 영향이 적은 방식으로 제공한다. 화면 변화는 애니메이션·hover·focus·스크롤·이전 상태의 영향과 구분한다. 원본 자료를 보존하고 선택한 파일의 해시/버전을 기록하면 다음 검토에서 기준 변경을 추적하기 쉽다.

반복 검토에는 [빈 검토 기록](assets/review-ledger.template.json)을 복사해 필요한 필드만 채운다. 빈 값은 미확인이며 0건 또는 정상 판정이 아니다. 기록 양식은 도구가 자동 판정하는 규칙이 아니다.

## 독자가 이해할 결과

처음 읽는 사람이 각 도구의 발견·미발견·추가 발견·확인 한계를 알 수 있게 쓴다. 도구 이름은 풀어 쓰고, 명세의 ID에는 버그 설명을 붙이거나 앞에서 표로 설명한다. 검토자가 만든 내부 식별자나 “원보고서”, “관찰 기록”, “부록” 같은 표현만으로 근거를 대신하지 않는다. 도구 이름과 페이지·항목을 직접 적는다. 지표를 바꿀 때는 이미 합의한 기준을 확인하고, 결과에 영향을 주는 새 판단이 필요하면 사용자에게 구체적인 선택을 묻는다.

## PDF를 요청한 경우

본문을 새 PDF 코드로 다시 구현하지 않는다. [문서 JSON 양식](assets/report-document.template.json)에 내용을 넣고 [공통 PDF 플랫폼](references/pdf-platform.md)의 `scripts/render_report.py`를 사용한다. 렌더러는 표·본문·이미지·막대를 배치할 뿐 점수나 결함 판정을 만들지 않는다. 제공된 PDF/문서 제작 지침을 함께 적용하고, 렌더링한 페이지의 잘림·글꼴·표 분할·그림 가독성을 직접 점검한다.

첫 장에는 결과 비교와 요청된 수식을 함께 보여준다. 시각자료·근거 연결·개정본 전달 및 기존 기록 대조는 [PDF 플랫폼](references/pdf-platform.md)의 독자용 보고서 절을 따른다.

페이지 구성, 지표 개수, 그림 수, 화면 크기, 재확인 횟수는 과거 사례를 복제하지 말고 현재 요청에 맞춘다. 이 스킬은 외부 사이트 조작, 유료 API 호출, 저장소 push의 새로운 권한을 부여하지 않는다.
