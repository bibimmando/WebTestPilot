# Sidebar·하위 페이지 서비스 구조 개선안
기준일: 2026-10-10 · 기획 전용 · 현재 메뉴의 모든 leaf와 홈 Tasks/계정 기능을 검토

## 추천 정보 구조

현재 사용자에게 보이는 메뉴명은 UI 구현 기술보다 작업 목적을 드러내야 한다. Charts/Forms/Tables 같은 컴포넌트 이름을 그대로 서비스 메뉴로 유지하는 것보다 리포트/내 설정/업무 요청과 같이 역할을 붙이는 방향을 권장한다. 목적이 없는 갤러리를 억지로 독립 서비스로 만들지는 않는다.

```text
업무
  홈                    기존 Dashboard 재구성
  할 일                 기존 개인 task 확장, 새 전용 화면 구현 후
  일정                  기존 Calendar
  리포트                Charts 실제 업무 데이터 연결 후

협업
  메일                  기존 내부 Email
  채팅                  기존 실제 Chat
  구성원                공개 연락처 서비스 구현 후

선택 기능               실제 수요·범위 확정 후만 노출
  업무 요청             Forms + Data Table 통합
  장소                  Google/Vector Maps 통합, 지도는 보기 방식

헤더 현재 계정 메뉴
  내 프로필·환경설정    실제 저장 기능 구현 후
  계정 전환             기존 기능
  로그아웃              기존 기능

상황별 화면
  로그인 / 계정 생성 / 404 / 500
개발 자료(일반 업무 Sidebar 밖)
  UI Elements / Buttons / 샘플 차트·표·지도 / Mock 모드
```

회원 계정은 조직 membership 모델이 아니고 신규 shared 자료는 전체 활성 인증 사용자에게 보인다. 그래서 '팀 관리자/부서/프로젝트 공간'을 현재 메뉴처럼 그리지 않는다. 실제 자료가 없는 리포트/신규 Tasks/구성원 등을 링크만 먼저 노출하는 방식도 피한다. 기존 기능을 사용할 수 있는 초기 단계에서는 홈/일정/메일/채팅과 계정 전환이 중심이다.

## 공용화와 합치기

Forms의 실제 자기 설정은 계정 메뉴로 이동한다. 별도 요청 작성의 필요가 확인되면 요청 목록의 작성 dialog/상세 form으로 Forms 디자인을 재사용한다. Data Table은 그 요청 목록이 되고 하나의 canonical 요청 객체·상태를 사용한다. '요청 작성'과 '요청 관리'를 서로 다른 저장소나 메뉴로 복제하지 않는다.

UI Elements/Buttons는 제품 화면의 공통 디자인과 실제 동작에 쓰는 자료다. 접근 가능한 모달·탭·진행/실패/확인 상태는 모든 실제 기능의 UX 개선으로 적용하고 독립 학습/실습 기능을 우선 만들지 않는다. 개발 자료를 유지하면 업무 화면과 분명히 분리한다.

Maps는 주소/장소 수요가 있는 경우에만 하나로 합친다. Vector world 지도는 지도 종류가 다르다는 이유로 별도 메뉴가 될 필요가 없다. 실제 지점이 없으면 지역 분석을 만들지 않고 샘플로 남겨 일반 서비스에서 숨긴다.

Blank는 홈의 정해진 카드 구성을 바꾸는 설정 진입으로 활용한다. 임의 section·프로젝트 canvas·별도 작업대 도메인을 새로 만들지 않는다. 오류/로그인/가입은 서비스 이용 중 상황에 따라 필요한 화면이며 Components 메뉴의 일반 업무 항목에서 제외한다.

## 페이지 목적에 맞는 제안

### W05. 실제 내 프로필·환경설정과 계정 전환 안내

**현재 상태:** 실제 인증과 최대10개 계정 추가/전환/제거가 있다. Forms profile은 John/Doe 샘플이며 저장하지 않는다. 계정 전환은 전체 재로드로 미저장 입력을 버린다.

**추가·개선할 기능:** 내 표시명·기본 시간대·홈 표시 설정을 실제 계정에 저장한다. 현재 계정을 헤더에서 잘 보이게 하고 미저장 작성 중 전환하려면 보관/취소/전환 결과를 설명한다. 저장할 수 있는 초안은 사용자가 선택한 경우에만 보관한다.

**필요한 이유:** 현재 누구로 작업 중인지 분명해야 하고 설정 화면의 가짜 저장·이름을 실제 개인 설정으로 바꿔야 한다.

**사용 시나리오:** 내 설정에서 표시명/시간대 저장 → 홈/일정에 적용 → 작성 중 계정 전환 → 저장 안 된 내용 안내 → 취소 또는 명시적 초안 저장 후 전환.

**예상 화면 구성·클릭 동작:** 헤더 account menu: 내 프로필/환경설정/계정 전환/로그아웃. 설정은 기본 정보·시간대·표시 탭, Role과 내부주소는 일반 편집에서 제외.

**기존 기능과의 연계:** User.display_name과 기존 accounts API를 재사용한다. 계정 전환·브라우저별 grant/로그아웃 정책은 유지한다. 시간대 변경은 기존 일정의 저장된 timezone을 소급 변환하지 않는다.

**구현 난이도:** Medium. 새 profile/preferences API·revision 및 auth/accounts-ui dirty 안내 예상. 계정별 draft와 화면 정보 격리. password reset/role 관리/탭별 독립 계정은 범위 밖.

**선행 조건·미결정 사항:** 자기 profile PATCH·개인 preference 저장; W15와 같은 설정 모델. 전환 사전 안내는 세션 만료/서버 강제 변경을 막지 않는다.

**기존 기능과의 차이:** 기존 계정 전환을 신규로 제안하는 것이 아니라 실제 설정과 미저장 입력 UX를 보완.

**우선순위:** High · 서비스 가치 94/100 · 권장 단계 2.

### W06. 업무 내용까지 찾는 통합 검색

**현재 상태:** command palette는 NAV 페이지와 동작 검색이다. 각 Email·Calendar·Chat 방 이름 검색은 있으나 내용을 여러 기능에서 한 번에 찾지 못한다.

**추가·개선할 기능:** 기존 페이지 검색을 유지하고 내 메일·할 일·접근 가능한 일정·대화의 제목/내용을 유형별 결과로 찾는다. 사용자에게 보이는 결과와 상세 권한을 동일하게 검사한다.

**필요한 이유:** 정보가 어느 기능에 있었는지 기억하지 않아도 작업을 다시 찾을 수 있다.

**사용 시나리오:** '분기 보고' 검색 → 메일/할 일/일정 결과 탭 → 작성자·날짜·일치 부분 확인 → 해당 상세 이동.

**예상 화면 구성·클릭 동작:** 헤더 검색, 유형 탭, 최근 query는 선택적으로 보관, 결과 제목·짧은 일치 문장·날짜·대상 배지. 처음에는 제목 검색, 메시지 본문은 성능 검토 후 확장.

**기존 기능과의 연계:** W02 deeplink, 기존 query 로직·Calendar visibility·Chat membership·메일 owner를 공유한다.

**구현 난이도:** High. 허용 자원별 서버 검색과 타입별 cursor/limit 예상. 현재 users/search나 NAV palette를 전체 내용 검색 API로 오인하지 않는다.

**선행 조건·미결정 사항:** 도메인별 검색 계약·데이터량/페이지 처리·권한 재검사. 계정 전환 시 검색 결과 제거.

**기존 기능과의 차이:** 새 업무 데이터가 아니라 현재 자료를 발견하는 공통 진입점. 초기 검색 범위는 작게 시작.

**우선순위:** Medium · 서비스 가치 77/100 · 권장 단계 3.

### W08. Charts를 개인 업무 리포트로 전환

**현재 상태:** Charts는 시드 데이터·PNG export. Dashboard의7일 생성/발신 차트는 DB 기반이지만 메일 폴더 이동·자료 삭제로 과거 수치가 바뀔 수 있다.

**추가·개선할 기능:** 사용자가 기간별 완료한 할 일·남은 업무·일정 참여 현황을 확인하고 자신의 업무 기록을 요약해서 내보낸다. 현재 자료 기반 지표와 기록 시작 이후의 완료 추이를 구분한다.

**필요한 이유:** 가짜 매출 그래프보다 실제 업무를 돌아보고 다음 일정을 조정하는 자료가 필요하다.

**사용 시나리오:** 이번 달 선택 → 완료/미완료 업무와 일정 확인 → 지난달 비교 가능한 데이터가 있으면 비교 → 요약 표/CSV 저장.

**예상 화면 구성·클릭 동작:** 기간·업무 유형 선택, 완료 추이/목록 표·지표 정의·데이터 기준 시각. 기본 홈에는 작은 요약만, 상세는 리포트 메뉴.

**기존 기능과의 연계:** 기존 Chart.js/활동 집계, W03 completedAt와 후속 변경 기록. 개인 통계 기본; 메시지 수를 사람 성과 순위로 만들지 않는다.

**구현 난이도:** Medium. 기간 조회·완료 집계 및 필요한 이력 수집 예상. '현재 Sent 메일 수'와 '불변 발신 건수'는 다른 지표로 표시한다.

## 이름·URL·가시성 변경 원칙

사용자에게 보이는 이름과 그룹은 바꿀 수 있다. 실제 구현에서는 기존 URL/북마크를 새 목적지에 연결하고 자원 상세 링크를 유지한다. 사용자에게 이미 제공된 private 자료의 공개 범위를 메뉴 이동 때문에 바꾸지 않는다. 신규 페이지 준비 전 메뉴 링크나 가짜 상태를 만들지 않는다.

회원 등록 정책과 운영 권한 모델은 미결정이다. 일반 '구성원' 페이지는 연락처이며 User 관리·권한 부여·계정 폐쇄 기능이 아니다. 정상 가입 페이지가 있다는 사실만으로 회사 초대/승인제 membership이 구현되어 있다고 쓰지 않는다.

서비스를 한국어로 운영할지 다국어로 할지도 별도 결정이다. 위 메뉴명은 역할 설명을 위한 한국어 권장명이며 현재 모든 영문 UI를 번역했다는 뜻이 아니다.
