# 프로젝트 개요

기준일: 2026-10-13 (Asia/Seoul). 현재 저장소의 코드를 조사해 작성했다.

## 목적과 현재 단계

웹 테스트 에이전트가 결함을 얼마나 잘 발견하는지 평가하기 위한 샘플 웹사이트다. 정상 동작 사이트를 Baseline으로 유지하고 향후 Git 브랜치에서 소스를 직접 수정해 의도적인 결함을 주입한다. 결함 토글 시스템은 개발 방식으로 사용하지 않는다. 기존 버그 문서는 과거 명세이며 구현 완료 목록이 아니다.

인증과 협업 기능, 데이터 충돌 방지 및 회귀 테스트가 구현되어 있다. 이번 작업은 문서만 재구성했으며 사이트의 정상 동작 전체를 새로 검증한 작업은 아니다.

## 전체 구성과 주요 기능

프론트엔드는 HTML, JavaScript, SCSS와 Webpack으로 구성된다. Python FastAPI 서버가 API와 빌드된 화면을 제공한다. 데이터는 기본적으로 SQLite에 저장하고 SQLAlchemy와 Alembic으로 접근·변경 이력을 관리한다.

| 기능 | 현재 역할 |
|---|---|
| Dashboard | 실제 일정·메일·채팅·개인 작업의 요약과 빠른 작업 입력 |
| 인증·계정 전환 | 가입, 로그인, 같은 브라우저에서 최대 10개 계정 등록·전환·제거 |
| Email·Compose | 등록된 내부 계정 간 텍스트 메일, 초안, 검색, 폴더, 별표, 고정 Label |
| Calendar | 공유 일정 생성·수정·삭제, 반복, 시간대, 참석자와 응답, 개인 기존 자료 가져오기 |
| Chat | 실제 계정 간 대화와 공유 대화방, 실시간 알림, 이력과 읽음 처리; 별도 Mock 예제도 존재 |
| Tasks | 계정별 개인 작업, 완료 시각, 메일·일정·채팅에서 연결한 작업 |
| Settings | 프로필, 시간대·테마·홈 카드·채팅 즐겨찾기 등의 계정 설정 |
| People·Search·Attention·Reports | 사용자 디렉터리, 접근 가능한 자료 검색, 확인할 항목, 개인 작업 완료 보고서 |
| 예제 및 기타 화면 | UI·버튼·지도 예제, Charts→Reports와 Forms/Blank→Settings 연결, 오류 화면 |

내부 메일은 외부 SMTP/IMAP과 연결되지 않는다. 첨부파일은 Mock 메일에서만 지원한다. 신규 일정은 공유로 생성되므로 모든 데이터를 계정 전용이라고 이해하면 안 된다. 개인 작업·메일·설정은 계정별로 관리하고 공유 자원은 별도의 권한 규칙을 따른다.

## 실행과 테스트 환경

이미 의존성과 `dist/`가 준비되어 있으면 저장소 루트에서 `start_server.bat`로 서버를 실행하고 `http://127.0.0.1:8000/signup.html`에서 가입한다. 화면 개발은 백엔드를 켠 상태에서 `npm start`로 4000번 포트를 사용한다. 자세한 환경 설정과 설치·빌드는 [개발 문서](CODEX_DEVELOPMENT_CONTEXT.md#5-프로그램-실행-방법)를 참조한다.

Vitest/jsdom 프론트 단위 테스트, pytest 백엔드 테스트, Playwright E2E, ESLint/Stylelint와 Production build가 준비되어 있다. pytest는 임시 DB를 사용하고 브라우저 테스트는 자체 서버와 별도 DB를 만든다. 개발 DB에 평가나 테스트 데이터를 섞지 않는다. 이번 문서 작업에서는 기능 테스트·빌드를 실행하지 않았으며 문서 보존, 링크, 소스·데이터 불변 여부를 검사했다.

## 문서와 향후 방향

모든 현재 문서의 진입점은 [README.md](README.md)다. Codex는 이 개요 대신 [CODEX_DEVELOPMENT_CONTEXT.md](CODEX_DEVELOPMENT_CONTEXT.md)를 우선 읽는다. 기존 기술 자료는 `arxive/`, 사람용 자료는 `archiveForHuman/`, 버그 자료는 `bugs/`에 원본 그대로 보존했다.

다음 개발은 정상 기준 상태와 검증 근거를 확정한 후 결함별 명세·독립 브랜치·재현 절차를 마련하는 것이다. 통합 후 의도한 결함의 재현과 정상 기능의 불필요한 회귀를 함께 확인한다. 평가용 Ground Truth는 웹 테스트 에이전트에 노출하지 않는다.
