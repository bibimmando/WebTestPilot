# WebTestPilot Playwright 크롤러 구현 계획

## 1. 목표

이 프로토타입의 목적은 웹사이트를 무작정 AI에 전달하는 것이 아니라, Playwright로 먼저 탐색·수집·판정·압축하여 다음 두 결과를 분리하는 것이다.

1. HTTP 오류, 자바스크립트 예외, 깨진 리소스처럼 코드로 확정할 수 있는 결과
2. 버튼을 눌러도 변화가 없는 이유, 검색 결과의 의미처럼 문맥 판단이 필요한 AI 후보

초기 버전은 허가된 테스트 사이트를 대상으로 하는 동일 출처(same-origin), 비파괴(safe interaction) 크롤러다.

## 2. 탐색 전략 결정

순수 DFS는 한 경로를 깊게 따라가므로 무한 달력·페이지네이션·동적 URL에 빠지기 쉽다. 순수 BFS는 얕은 범위를 안정적으로 덮지만 중요한 페이지와 단순 페이지를 같은 순서로 처리한다.

따라서 이 프로토타입은 **우선순위가 있는 BFS(best-first BFS)** 를 사용한다.

- 기본적으로 깊이가 얕은 상태를 우선한다.
- 새 경로, 폼, 상호작용 요소, 오류 신호가 많은 페이지의 우선순위를 올린다.
- 반복 경로, 깊은 상태, 이미 많이 본 URL 패밀리는 감점한다.
- 동점이면 먼저 발견한 항목을 먼저 처리하여 결과를 재현 가능하게 한다.

이 방식은 BFS의 넓은 커버리지와 우선순위 큐의 정보가치 기반 탐색을 결합한다.

## 3. 여섯 요구사항의 구현

### 3.1 정적/동적 요소 측정과 AI 라우팅

- 각 페이지에서 링크·이미지·리소스·폼 등 정적 신호 수와 버튼·탭·메뉴·입력·hover 후보 등 동적 신호 수를 센다.
- 결정적 검사기가 확정한 문제는 AI 큐에 넣지 않는다.
- 상호작용 결과가 모호하거나 의미 판정이 필요한 경우에만 축약된 `AIReviewCandidate`를 우선순위 큐에 넣는다.
- AI 입력에는 전체 HTML 대신 제목, 헤딩, 핵심 컨트롤, 폼 요약, 행동 전후 차이, 관련 오류만 포함한다.
- 예상 입력 토큰 수를 기록하여 추후 `priority / estimated_tokens` 방식으로 비용 대비 가치를 조정할 수 있다.

### 3.2 탐색 알고리즘

- `heapq` 기반 `PriorityFrontier`가 페이지 방문 후보를 관리한다.
- 깊이, 발견 경로, 신규성, 상호작용 가치로 점수를 계산한다.
- 실제 상태 그래프의 노드와 간선은 결과 JSON에 저장한다.

### 3.3 탐색 범위 제한

- 최대 페이지, 최대 깊이, 최대 실행 시간, 페이지당 최대 행동 수, 큐 최대 크기를 동시에 적용한다.
- 동일 URL당 상태 수와 동일 경로 패밀리당 URL 변형 수를 제한한다.
- 연도·날짜·연속 숫자·UUID를 `{date}`, `{n}`, `{uuid}`로 묶어 무한 달력과 ID 열거를 차단한다.
- 로그아웃, 삭제, 결제, 구매, 제출 등 파괴 가능 행동은 기본적으로 실행하지 않는다.
- 동일 출처 밖의 링크는 기본 차단한다.

### 3.4 중복 방지

접근성 트리 전체는 크고 페이지별 변동이 많아 매번 AI 전처리용으로 사용하기에는 비싸다. 대신 다음 두 지문을 결합한다.

- 정규화 URL 지문
- 보이는 헤딩·컨트롤·입력 필드·내부 링크·주요 텍스트를 정렬·축약한 semantic DOM 지문

URL이 같아도 모달·탭·메뉴가 열린 상태처럼 semantic DOM이 달라지면 별도 상태로 기록하되, URL별 최대 상태 수를 초과하면 중단한다.

### 3.5 URL 정규화

- fragment 제거, host/scheme 소문자화, 기본 포트 제거, 경로 정리, query 정렬을 수행한다.
- `utm_*`, `gclid`, `fbclid`, 세션 추적값 등은 기본 제거한다.
- 의미 있는 query는 기본 보존한다. `--drop-query-param`과 `--keep-query-param`으로 사이트별 정책을 바꿀 수 있다.
- 정규화 결과를 방문 키로 사용하여 파라미터 순서만 다른 중복 방문을 막는다.

### 3.6 사용자 상호작용으로 나타나는 상태 수집

- 버튼, 탭, 메뉴, disclosure, summary와 `aria-haspopup`/tooltip 후보를 찾는다.
- 클릭과 hover 전후의 URL, semantic DOM, 가시 텍스트, 네트워크, 콘솔 오류 차이를 기록한다.
- hover 또는 클릭 뒤 새로 나타난 내부 링크를 탐색 큐에 추가한다.
- 행동마다 원 페이지로 복귀하여 이전 행동이 다음 행동에 오염을 주지 않게 한다.

## 4. 모듈 구조

```text
webtestpilot_crawler/
├─ cli.py             CLI와 설정 조립
├─ config.py          탐색 예산·URL 정책
├─ crawler.py         Playwright 실행 루프와 상태 그래프
├─ detectors.py       결정적 검사기와 페이지 분류
├─ fingerprint.py     축약 DOM 수집 및 상태 지문
├─ interactions.py    안전한 click/hover 실행
├─ models.py          관찰·행동·이슈·AI 후보 모델
├─ priority.py        페이지/AI 우선순위 큐
├─ reporter.py        JSON/JSONL/Markdown 결과
├─ scope.py           탐색 범위·변형 제한
└─ url_normalizer.py  URL 정규화와 경로 패밀리화
```

## 5. 1차 완료 기준

- 로컬 테스트 사이트에서 중복 query URL을 한 번만 방문한다.
- 무한 달력 형태의 경로가 설정된 variant 한도에서 멈춘다.
- hover 메뉴에서 처음에는 숨겨진 링크를 발견한다.
- HTTP 4xx/5xx, page error, console error, failed request, broken image, 가로 overflow를 규칙으로 탐지한다.
- `crawl_report.json`, `ai_queue.jsonl`, `summary.md`를 생성한다.
- 전체 HTML 없이 AI 후보를 만들고 예상 토큰 수를 기록한다.

## 7. 안전 경계

본 크롤러는 소유했거나 명시적으로 테스트 허가를 받은 사이트에서만 실행한다. 기본 safe mode는 파괴 가능 행동과 외부 출처 이동을 차단하지만, 완전한 무해성을 보장하는 보안 경계는 아니다. 실제 운영 서비스에는 읽기 전용 테스트 계정과 격리된 스테이징 환경을 권장한다.
