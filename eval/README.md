# 평가 (`eval/`)

제품 코드(`qa/`)와 분리한 평가 자료. **정답지(버그 위치·내용)는 이 폴더에만 두고, 계획·실행·분류 모델 입력에 넣지 않는다** ([AGENTS.md](../AGENTS.md)).

| 위치 | 내용 |
|---|---|
| `plans/` | 고정 계획 3개(목록·모달·폼)와 출처(`meta.json`). 정상 개발 fixture에서 Codex CLI로 만들었다 |
| `variants/bug-1/` | 같은 URL로 버그를 심은 페이지와 정답지 `bugs.json`. 없는 파일은 정상 앱(`qa/test/fixtures`)에서 준다 |
| `variants/bug-2/` | M2 구조(아이콘 수량 버튼·열 때마다 바뀌는 관련 상품·필터 초기화)의 버그 변형과 정답지. 고정 계획 없이 새 탐색(Q47 확인)에만 쓴다 |
| `run.mts` | 앱을 8765 포트로 띄우고 계획을 2·3단계로 끝까지 실행한 뒤 정답지와 비교 |
| `results/` | 실행별 `summary.json` (Git 제외). 실행 폴더 자체는 `qa/runs/eval-*`에 남는다 |

```powershell
node eval/run.mts                  # 정상 앱: 후보가 나오면 모두 오탐 후보
node eval/run.mts --variant bug-1  # 버그 변형: 범위 안 버그의 탐지/미탐
```

유료 API는 부르지 않는다. AI 분류가 필요한 항목은 `uncertain`으로 남는다.

## 2026-10-15 결과

| 앱 | 결과 |
|---|---|
| 정상 | 검사 31개 통과(휴리스틱 1개 포함), 후보 0, 서버에 닿은 쓰기 요청 0 |
| bug-1 | B1·B2 탐지 + 재현(검사 6개), B3는 요구사항 밖이라 계획에 없음, 설명되지 않는 후보 0 |

## 이 결과로 말할 수 없는 것

- **일반화 성능이 아니다.** 계획을 만든 앱과 평가한 앱이 같은 개발 fixture다. 독립 앱 평가(설계 8장 5단계)는 따로 해야 한다.
- 계획은 Codex(GPT 계열)가 만들었다. Claude API 결과와 섞어 비교하지 않는다.
- 탐지는 페이지 단위로 맞춘다. 한 페이지에 범위 안 버그가 여럿이면 버그별로 구분하지 못한다.
- 이 실행에서는 AI 분류가 필요한 실패가 나오지 않아 그 경로를 지나지 않았다.
