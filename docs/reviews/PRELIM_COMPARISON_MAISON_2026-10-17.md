# 중간발표 예비 비교 — Maison, Claude API (2026-10-17)

> 게시판 fixture 비교([결과](PRELIM_COMPARISON_2026-10-17.md))에 이은 두 번째 예비 비교다.
> - Maison은 우리 시스템을 여러 번 고친 **개발 사례**라 우리 쪽에 크게 유리하다. 이 결과로 일반화 성능을 주장하지 않는다.
> - 정답표는 이 작업에서 열지 않았다. 아래 "채점" 칸은 사람이 채운다.

## 조건

- **모델·예산:** 세 도구 모두 Claude Opus 5.5(API)로 1회씩, 도구마다 비용 상한 $10과 시간 상한 40분을 뒀다.
  - 우리 시스템은 분류에 Sonnet 5.5를 함께 쓴다.
  - Claude Code CLI를 2.1.121에서 2.1.302로 올렸다(Opus 5.5 지원).
- **입력:**
  - 시작 URL `http://13.124.7.113:8081/`만 줬다. 요구사항은 없다.
  - 세 도구 모두에게 같은 문구로 "서버에 저장되는 제출(구독·주문·결제·가입·리뷰)은 하지 말 것"을 지시했다.
  - 우리 시스템은 쓰기 요청도 코드로 막는다. 이번 실행에서 막힌 쓰기는 `POST /api/subscribe` 1건이다.
- **실행 방식:**
  - **우리 시스템:** 제품 CLI(`src/cli.ts`, 코드 `e3ef8dc`), 탐색 병렬 3, 실행 워커 2, 재현 1회, 보고서 생성.
  - **Playwright Test Agents:** `claude -p --bare`, 공식 Planner·Generator 지침, 공식 `run-test-mcp-server`. Healer는 쓰지 않았다.
  - **dogfood:** `claude -p --bare`, agent-browser 0.39.1, dogfood 스킬 원문.
  - 다른 두 도구는 `--bare`라 우리 프로젝트 지침(CLAUDE.md)을 읽지 않는다.

## 해석 (관측, 주장 아님)

- **완주와 비용**
  - 우리 시스템과 dogfood는 10분 안팎에 끝났다. Playwright Planner는 같은 상한에서 두 번 모두 계획 단계에 가지 못했다.
  - Planner 지침은 "모든 상호작용 요소를 철저히 탐색"하라고 하고 시간·턴 안내가 없다. 페이지가 많은 사이트에서는 상한 안에 끝나지 않을 수 있다.
  - 우리 시스템은 남은 턴 안내·정체 종료·템플릿별 대화로 이 문제를 다룬다.
- **찾은 것의 성격**
  - 기능 결함(장바구니·수량·위시리스트)은 두 도구가 모두 찾았다.
  - 우리 시스템만 낸 것은 "앱 자체 모순"을 비교하는 검사(관련 상품 링크 대상, 필터 해제)에서 나왔다. 같은 템플릿의 다른 페이지에서도 같은 결함을 확인했다(C4).
  - dogfood만 낸 것은 내용·화면·사용성·접근성 쪽이다(배송 문구 모순, 겹침, 스크롤, 접근 가능한 이름, 언어 혼용). 우리 시스템은 모바일·시각 검사와 품질·사용성 규칙(③ 묶음)이 아직 없어 이런 것을 결함 후보로 내지 않는다(일부는 관찰로만 남김).
- **증거:**
  - 우리 시스템은 항목마다 기대·실제·근거 인용과 자동 재현 결과를 남긴다.
  - dogfood는 단계별 스크린샷과 서술형 재현 절차를 남긴다.
  - 채점 뒤에 맞은 주장과 틀린 주장의 비율을 봐야 어느 쪽 주장이 더 믿을 만한지 말할 수 있다.
