## 발견한 한계와 수정 사항 (우선순위 순)

### 1. snapshot 파서 버그 — 클릭 가능한 요소를 고정하지 못함 (높음, 코드 버그)

Playwright는 클릭 가능한 요소에 `link "…" [ref=f1e48] [cursor=pointer]:`처럼 ref 뒤 속성을 붙인다. `browser.ts`의 줄 정규식이 이 형태를 읽지 못해 **pin 실패 16건 중 13건이 "snapshot에 없는 ref"** 였다. 모델은 카테고리 버튼을 고정하지 못해 **Tab 5번 + Enter** 같은 키보드 우회 계획을 만들었다(포커스 순서가 바뀌면 깨진다). 탐색 33턴의 절반가량이 재시도였다.

- 근본 원인: 테스트 fixture에 이 줄 형태가 없었다.
- 수정: ref와 속성을 줄에서 따로 추출. fixture·`parseSnapshot` 테스트에 `[cursor=pointer]`·`[active]` 등 속성 줄 추가.

### 2. 텍스트 읽기 기준 불일치 — 오탐 4개가 "재현"까지 됨 (높음)

탐색 때 모델은 접근성 snapshot의 DOM 텍스트 `Textiles`를 보고 기대값을 정했다. 실행의 `check`는 `innerText`로 읽어 CSS `text-transform` 결과인 `TEXTILES`를 얻었다. 4개 모두 `mismatch → reproduced`.

- 수정: `read: 'text'`는 모델이 본 것과 같은 기준(정규화한 `textContent`)으로 읽는다.
- 더 큰 교훈: **결정적인 자동화 오류도 재현된다. `reproduced`는 결함 확정이 아니다.** 지금은 `mismatch`가 AI 분류를 거치지 않는다. 불일치 후보도 증거(스크린샷 포함)로 분류하거나, 표시 차이(대소문자·공백)를 별도 상태로 구분해야 한다.

### 3. 식별 규칙이 흔한 UI를 막음 — R3·R4 계획 불가 (높음)

수량 표시 `1`은 "숫자만 있음", 증감 버튼은 아이콘뿐이라 "이름 없음"으로 거부됐다. **탐색 모델은 "증가 버튼을 두 번 눌러도 수량이 1에서 바뀌지 않음(결함 의심)"을 관찰했지만 계획에 담을 방법이 없어 unplanned 사유에만 적었다.**

- 수정 방향: 유일하게 식별되는 작은 상위 그룹 안에서는 역할+순서로 식별을 허용(예: 수량 그룹의 [−][값][+]). 그룹 자체의 유일성과 구성원 수를 pin 때 검증한다.
- 탐색 중 관찰한 이상은 `observations` 필드로 받아 보고서에 따로 남긴다(검증된 결함과 구분).

### 4. 관계형 요구사항을 표현할 수 없음 + 동적 콘텐츠 (중간)

R2("누른 카드의 상품 상세가 열린다")는 **"클릭한 카드 이름 = 열린 상세 제목"** 이라는 관계식이다. 지금 계약은 고정 기대값만 지원해서, 모델은 탐색 때 본 카드 하나를 골라 그 이름을 기대값으로 고정했다. 관련 상품 목록은 로드마다 달라서 S5의 대상 카드가 실행 때 없었다.

- 이 실행에서 AI 분류가 **실제 결함 단서**를 찾았다: 관련 상품 카드 "Woven Lounge Chair"가 `/product/harvest-dining-table`로 연결된다. 그러나 계획과 연결되지 않아 `uncertain`으로 남았다.
- 수정 방향: 기대값을 "실행 시 다른 대상에서 읽은 값"으로 지정하는 관계 비교(`expected_from: T#`)를 추가. pin할 때 대상이 재로드 후에도 있는지 확인해 동적 영역을 표시한다.

### 5. 기타 (낮음)

- 이동 후 ref 접두사가 바뀌어(f1→f2) 오래된 ref 오류가 몇 번 났다. 원문 오류 `Invalid frame in aria-ref selector`를 그대로 보여줘서 안내가 약하다.
- 프롬프트 캐시는 정상 동작했다(매 턴 새 입력 2토큰, 나머지는 캐시 읽기). 1번을 고치면 턴 수와 비용이 더 줄 것으로 예상하지만 측정하지 않았다.
