## 결과 자세히

### 1. 카테고리 필터 (R1) — 모두 통과

- `Lighting`·`Ceramics` 버튼을 직접 고정해 눌렀다. 첫 실측의 키보드 우회가 사라졌다(M1 파서 수정의 효과).
- 필터 후 카드 수, 다른 카테고리 카드가 사라지는지, 해당 카테고리 카드가 보이는지를 검사해 모두 통과했다.
- 시작 시점에 본 전체 카드 수(13개)는 관찰값 근거라 `passed_observed`로 따로 집계됐다.

### 2. 카드 → 상세 (R2) — 목록 카드는 통과, 관련 상품 링크는 불일치 2건

| 시나리오 | 내용 | 결과 |
|---|---|---|
| S3 | 전체 목록에서 카드 클릭 → 그 상품 상세 | 통과 |
| S4 | Lighting 필터 후 카드 클릭 → 그 상품 상세 | 통과 |
| S5 | Arc 상세의 관련 상품 "Orb Table Lamp" 클릭 → Orb 상세 | **불일치** — 실제로는 **Harvest Dining Table** 상세가 열림. 재실행에서도 같음(재현됨) |
| S6 | Orb 상세의 관련 상품 "Arc Pendant Light" 클릭 → Arc 상세 | **불일치** — 역시 **Harvest Dining Table** 상세가 열림. 재현됨 |

- 기대값의 근거는 요구사항 R2("누른 카드에 적힌 상품의 상세가 열린다")다.
- 10/12 분석의 개발용 버그 목록에 있는 "관련 상품 이름과 이동 대상 불일치(N1)"와 같은 유형으로 보인다. 다만 이건 정답지 대조가 아니라 유형 비교다.

### 3. AI 분류가 "판단 불가"로 남긴 이유

AI(Sonnet)는 두 건 모두 **"카드에 적힌 상품과 링크 대상이 어긋나는 앱 결함처럼 보인다"** 고 썼다. 그런데도 `uncertain`을 골랐다. 근거는 이랬다.

> "시작 시점 기록은 로딩 중 상태뿐"이라 자동화가 다른 링크를 눌렀는지 가를 수 없다.

확인해 보니 사실이다. 상세 페이지(S5·S6)의 **시작 시점 snapshot이 로딩 중 화면으로 저장됐다**. 상품 제목이 없고 로딩 표시만 있었다. `start()`가 페이지 `load` 직후 바로 snapshot을 찍는데, 이 SPA는 그 뒤에 내용을 그린다. 행동 직전·직후 증거도 아직 없다(M4 범위). 그래서 "Arc 상세에서 Orb 링크를 눌렀다"를 증거로 보여 줄 수 없었다.

- AI가 근거 없이 결함으로 확정하지 않고 보류한 것은 설계 의도대로다.
- 고칠 곳은 증거 쪽이다. 아래 M2 반영 사항 2번.

### 4. 수량 증감 (R3·R4) — 여전히 계획 불가

증감 버튼은 이름 없는 아이콘이고, 수량 표시는 숫자뿐이라 고정이 거부됐다. 탐색 에이전트는 "증감 버튼에 aria-label이 있어야 테스트할 수 있다"며 미계획 사유를 남겼다. M2의 "작은 그룹 안 역할 + 순서 식별"이 들어가야 해결된다.

## M2에 반영할 사항

| # | 문제 | 원인 | 반영 |
|---|---|---|---|
| 1 | 수량 증감 미계획 | 아이콘 버튼·숫자 표시를 식별할 수 없음 | 설계에 이미 있는 M2 "그룹 안 역할 + 순서 식별" |
| 2 | 진짜 결함 후보가 "판단 불가"로 남음 | 시작 증거가 로딩 중 화면. 행동 전후 증거 없음 | **`start()`가 준비될 때까지 기다린 뒤 시작 증거를 찍게 한다**(M2 `precondition`·`ready`와 함께). 행동 전후 증거는 M4 |
| 3 | 관련 상품 시나리오가 특정 카드 이름에 기대값을 고정 | 관계 비교가 없어 "누른 카드 이름 = 열린 상세 제목"을 표현 못 함 | M2 `expected_from` (관측 참조) |
| 4 | 상세 확인을 설명 문단의 `visible`로 대신함 | 제목 읽기 대신 고유 문단이 보이는지로 확인 | 관계 비교가 들어가면 제목 텍스트 비교로 바뀔 것으로 예상 |

## 이 결과로 말할 수 없는 것

- 단일 실행·단일 개발 앱이다. 독립 앱 성능이 아니다.
- 관련 상품 링크 불일치는 재현됐지만 시스템 판정은 "판단 불가"다. 결함 확정이 아니다.
- 비용은 토큰 사용량 기준 추정이며 청구서가 아니다.
