# 2차 — Claude 답변과 남은 쟁점

## 받아들이는 정정

- **A1:** "우연"이라는 인과 주장은 철회한다. 관계 검사의 기준이 되는 관측(클릭 전 카드 이름, 변경 전 목록)은 허용해야 한다는 점에 동의한다.
- **A2:** M5(쓰기·로그인)와 M4(시각 판정)를 과소평가했다. "계산값만으로 UI 대부분"도 과했다. 계산 검사는 최소 집합(이전 관측 참조, 수치 비교, 목록 조건, scroll, overflow)만 추가하고 임의 CSS·겹침 표현 언어는 보류하자는 데 동의한다.
- **A3:** trace에 콘솔·네트워크가 이미 있다. 빠진 것은 구조화 추출과 판정 연결이다. 정상 거절(401·422)과 정책 차단은 결함이 아니다.
- **B1:** 이미 쓴 코드는 C3 승인 근거가 아니다. 문구를 고친다.
- **새 지적 모두 동의:** 탐색 배분, 템플릿 묶기 오류, 적응 실행의 결정성, 분류 입력에 기대·실제를 구조화 필드로 전달하고 분류가 원래 불일치를 덮지 않기, 전체 트리 해시의 재현 불가 오판, 일정(11/19까지 약 5주).

## 남은 쟁점 — 각각 가장 단순한 안을 제안한다. 동의/반대와 더 단순한 안이 있으면 알려 달라.

1. **적응 실행(4a)을 아예 미룬다.** 지금까지 고정 실행 실패는 0건(Maison 12/12, fixture 전부)이다. 6.1의 "고정 실행 실패율 20% 초과 시 재검토" 조건만 남기고 M4에서 뺀다. 그 자리에 실패율 측정만 넣는다.

2. **시작 상태 비교를 "선언한 시작 조건"으로 바꾼다.** 전체 접근성 트리 해시 대신, 계획의 각 시나리오가 시작 조건을 검사로 선언한다(`after: start`인 검사 = 시작 조건). 재현은 그 시작 검사들이 최초와 같은 값으로 통과할 때만 같은 시작 상태로 본다. 별도 계약을 만들지 않고 기존 `after: start` 검사를 재사용한다. 충분한가?

3. **A1의 최소 규칙.** 다음 하나면 되는가: "`source.kind = observed`인 검사는 `after: start`(기준·시작 조건)이거나 `expected_from`(관계)만 허용한다. 행동 뒤의 검사가 고정 기대값을 가지려면 출처가 requirement·constraint·AI 추정 중 하나여야 한다." AI 추정이면 결과는 검토 대상으로 가지만 탐지는 된다.

4. **탐색 배분의 최소 안.** 전역 비용·행동 한도 하나 + 템플릿 순환: 사이트 지도의 미검사 템플릿을 순서대로 한 대화씩 열고, 템플릿당 상한은 "남은 예산 / 남은 템플릿 수"로 매번 다시 계산한다. 대화 안에서 변화 없는 행동이 N번 반복되면 그 템플릿을 끝낸다. 대화 이력은 템플릿이 끝나면 버리고 요약만 넘긴다. 이 정도면 되는가, 빠진 방어가 있는가?
