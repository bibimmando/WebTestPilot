# 중간발표 예비 비교 결과 (2026-10-17)

> [비교 계획](PRELIM_COMPARISON_PLAN_2026-10-17.md)에 따른 **예비 비교**다. 대상 fixture는 우리 시스템을 고치는 데 쓴 **개발 사례**라 우리에게 유리하다. 이 결과로 일반화 성능 우위를 주장하지 않는다. 미사용 독립 앱 비교는 M8·M9에서 한다.

## 조건

- **실행 주체:** 세 도구 모두 같은 Codex CLI(0.159.2, 기본 모델·reasoning)로 1회씩 실행했다. 우리 제품의 기본 경로(Claude API·Opus)와는 다르다.
- **입력:** 시작 URL(`http://127.0.0.1:<port>/`)과 허용 origin만 줬다. 요구사항·정답표·주입 위치는 어느 쪽에도 주지 않았다.
- **한도:** 실행마다 40분, 새 fixture 서버.
- **실행 방식:**
  - **우리 시스템(코드 `8e34172`):** Codex는 읽기 전용이고, 우리 MCP 도구로 탐색·계획한다. 실행·대조·재현·판정은 코드가 한다. 같은 템플릿 3페이지 실행과 재현 1회가 들어간다. AI 분류는 껐다.
  - **Playwright Test Agents:** Planner 지침 → Generator 지침, 공식 `run-test-mcp-server`. 생성된 테스트의 **최초 실행 결과**를 결함 주장으로 본다. Healer는 쓰지 않았다.
  - **agent-browser `dogfood`(0.39.1):** 스킬 문서를 그대로 줬다. Codex 쓰기는 저장소 밖 출력 폴더로 한정했다.
- **맞추지 못한 조건:**
  - 우리 시스템만 쓰기 요청을 막는다. 이번 fixture는 브라우저 저장소만 써서 세 도구 모두 GET 외 요청은 0건이었다.
  - Playwright 첫 시도는 제가 MCP 서버를 본 세션에 붙이지 않아 브라우저 없이 끝났다. 고친 뒤 다시 돌린 결과만 쓴다.
  - Codex 사용량 한도로 몇 실행이 중간에 멈췄다(아래 "실행 기록"). 멈춘 실행은 같은 조건으로 다시 돌린 결과를 쓴다.

이 6건은 심어 둔 결함은 아니지만, 모두 오탐으로 단정할 수도 없다. fixture가 일부러 단순하게 만든 부분(상세 페이지·인증 없음)이거나 실제 사용성 문제일 수 있어 **사람이 판정해야 한다**.

우리 시스템은 같은 점들을 결함으로 내지 않았다.
- **관찰로 남긴 것:** "게시글 항목을 눌러도 변화 없음", "비밀번호 라벨에 (필수) 없음", "인증 없이 관리자 선택 후 삭제됨"
- **질문으로 남긴 것:** "뷰어가 관리자를 선택하면 삭제까지 허용하는 것이 의도인가요?"

설계(판단 보류 + 질문)대로 동작한 것이다. 다만 이 항목들이 실제 결함이라면 우리 쪽은 "보류"로만 남았다는 뜻이기도 하다.

## 해석

- **이 fixture에서는 탐지로 도구를 가를 수 없다.** 세 도구 모두 5/5다. 차이는 정답 밖 주장을 다루는 방식에서 났다.
  - dogfood는 애매한 점도 결함으로 낸다(정상 버전에서 6건).
  - Playwright Agents는 실패한 테스트만 낸다.
  - 우리 시스템은 애매한 점을 관찰과 질문으로 남긴다.
- **우리 시스템의 강점으로 볼 수 있는 것(주장 아님, 관측):** 정상 버전 0건, 근거 종류의 고정, 자동 재현 판정, 구조화된 판정 파일. 개발 사례라 이 차이가 일반화되는지는 모른다.
- **약점:** 시간과 토큰이 가장 많이 든다. 애매한 사용성 문제(삭제 확인 없음·모바일 넘침)는 결함 후보로 내지 않는다. 모바일 검사와 사용성 규칙(③ 묶음)이 아직 없다.

## 다음에 할 것

- **변별력 있는 대상이 필요하다.** 화면만으로 드러나지 않는 결함이 든 앱이 있어야 한다. 예를 들면 같은 템플릿의 다른 페이지에만 있는 데이터 결함, 상태 유지, 서버 저장 흐름이다. 미사용 독립 앱(팀 확보)도 필요하다.
- 우리 시스템을 Claude API 경로(제품 기본값, 병렬 탐색)로도 같은 조건에서 돌려야 한다(유료, 승인 필요).
- dogfood의 정상 버전 주장 6건은 사람이 판정해 결과에 반영한다.
