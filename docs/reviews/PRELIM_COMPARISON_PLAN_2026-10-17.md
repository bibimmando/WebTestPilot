# 중간발표 예비 비교 계획 (2026-10-17)

> 설계 11장 중간발표 행·3.6 순서 6번. **예비 비교이며 최종 성능 주장이 아니다.** 비교 대상과 우리 시스템을 같은 표(발견 항목·근거·재현·오탐·비용·시간)로 정리한다.

## 비교 대상

| 이름 | 무엇 | 실행 방법 |
|---|---|---|
| **우리 시스템(v2)** | 사이트 지도 → 템플릿별 탐색·계획 → 결정적 실행 → 대조 → 분류 → 재현 → 판정 → 보고서 | Codex CLI가 개발용 MCP 서버(`qa/src/mcp.ts`)로 탐색·계획하고, 실행·판정·보고서는 코드가 한다(Q47 드라이버와 같은 경로). AI 분류는 끈다(유료 API 미사용) |
| **Playwright Test Agents** | Planner(탐색 → Markdown 계획) → Generator(테스트 코드) → 실행. Healer는 기대값을 바꿀 수 있어 최초 실행 결과를 따로 보존한다 | 이미 설치된 Codex 에이전트(`.codex/agents/playwright_test_*.toml`), `tools/playwright-agents/` |
| **agent-browser `dogfood`** | 탐색형 QA 스킬. 이슈 범주표를 따라 사이트를 써 보고 이슈 보고서(재현 절차·스크린샷)를 쓴다 | 설치 필요(`npm install agent-browser` + `agent-browser install`). Codex에 dogfood 스킬 문서를 주고 실행 |

## 같게 맞추는 조건

- **실행 주체·모델:** 세 쪽 모두 같은 Codex CLI(버전·모델·reasoning 기본값 기록). 우리 제품의 기본 경로(Claude API, Opus)와 다르다는 점을 결과에 적는다.
- **입력:** 시작 URL과 허용 origin만. 요구사항 없음. 정답표·주입 위치는 어느 쪽에도 주지 않는다.
- **한도:** 도구마다 1회, 실행당 시간 상한 40분. Codex 로그의 사용 토큰을 기록한다.
- **시작 상태:** 매 실행 새 브라우저 상태. fixture 서버는 실행마다 새로 띄운다.

**맞출 수 없는 조건(결과에 기록):**
- 우리 시스템은 쓰기 요청을 막지만, 다른 두 도구는 막지 못한다.
- Planner는 테스트 코드를 남기고, dogfood는 서술형 보고서를 남긴다.
- 우리 시스템은 같은 템플릿 페이지 3개에서 실행하고 재현을 1번 더 한다.

## 대상 앱과 채점

| 앱 | 용도 | 채점 |
|---|---|---|
| 사내 게시판 fixture 정상 | 오탐 측정 | 정상 버전에서 낸 결함 주장은 모두 오탐 후보이며, 사람이 확인한다 |
| 게시판 bug-3 (폼 길이·정렬·페이지 반복·권한 노출) | 탐지 | `eval/variants/bug-3/bugs.json`으로 사후 채점 |
| 게시판 bug-4 (등록 완료 안내 ↔ 목록 누락) | 흐름 결함 탐지 | `eval/variants/bug-4/bugs.json`으로 사후 채점 |
| Maison (선택) | 실제 앱 | 정답표는 이 작업에서 열지 않는다. 발견 목록만 정리하고 채점은 사람이 한다 |

**편향 주의:** 게시판 fixture와 Maison은 우리 시스템을 고치는 데 쓴 **개발 사례**다. 우리에게 유리하게 기울어 있으므로 이 비교로 일반화 우위를 주장하지 않는다. 미사용 독립 앱 비교는 M8·M9에서 한다.

## 결과 정리 형식

도구마다 발견 항목을 같은 칸으로 옮긴다.
- 칸: 페이지, 주장(무엇이 잘못됐나), 기대 근거(요구사항·화면 안내·일반 상식·추정), 실제, 재현 절차, 증거, 도구가 붙인 확신·심각도.
- 채점 표: 정답 결함별 탐지(맞음/부분/놓침), 정상 버전 주장 수(오탐 후보), 정답 밖 주장, 재현 가능 여부(같은 절차로 사람이 한 번 따라 해 봄), 사용 토큰, 시간.
- 근거 수준을 따로 센다. 근거 없는 추정이 맞은 것과 근거로 판정한 것을 같은 탐지로 세지 않는다.
