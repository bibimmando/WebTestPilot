## 2026-10-15 (6) · Claude · M2 (계획 계약 확장 + 그룹 안 순서 식별)

- 한 일:
  - **계획 계약** (`plan.ts`)
    - 관측 참조 `expected_from`: 같은 시나리오의 앞선 검사만 가리킬 수 있고, 근거로 observed는 쓸 수 없다. 같은 시점에 같은 값을 다시 읽어 비교하는 것은 거부한다.
    - 읽기 `url`·`items`를 추가했다. 비교에 not_equals·less·greater·all/any_*를 추가했다.
    - 근거 `constraint`를 추가했다. 탐색 중 모델에게 보여 준 텍스트 인용만 인정한다. `heuristic`은 `inferred`로 이름을 바꿨다.
    - `precondition`은 시작 시점 검사에만, 요구사항 근거가 아닌 검사에만 허용한다. `observations`를 추가했다.
    - 비교 함수 `compareValues`를 fixture와 reconcile이 함께 쓴다.
  - **실행**
    - `start()`가 `settle`(화면이 멈출 때까지 대기) 뒤에 시작 증거를 찍는다. `ready`를 기록하고 startHash는 없앴다.
    - 선행조건이 실패하면 시나리오를 멈춘다. 분류는 `precondition_failed`이고 결함 후보가 아니다.
    - 재현은 재실행에서 선행조건이 통과했는지로 판단한다.
    - 관측 참조 검사의 재현 서명은 값이 아니라 규칙이 다시 깨졌는지로 비교한다.
  - **대상 식별** (`browser.ts`)
    - 이름 없는 아이콘 버튼과 숫자 칸은 고유 라벨(anchor) 영역 안의 순서(nth/of, 최대 6개)로 고정한다.
    - 실행 때 라벨이 중복되거나 개수가 바뀌면 `shapeChanged`로 대상이 바뀐 것으로 처리한다.
    - `position` pin으로 바뀌는 목록의 요소를 순서로 고정한다.
    - 행동 전에 pin한 대상은 새로 열어도 있는지 확인한다(`stableOnReload`).
    - 목록 컨테이너를 그룹으로 고르면 그 안의 항목들을 그룹으로 본다(Q47에서 발견).
  - **문서와 프롬프트:** 탐색·분류 프롬프트를 갱신했다.
- 리뷰와 테스트: Codex 리뷰(P1 1건, P2 5건, P3 1건)를 모두 반영했다. 무료 테스트 68개 통과. eval bug-1 결과는 그대로다.
- Q47 확인(Codex CLI 구독, 새 탐색, 최종 코드, 새 fixture product·filter와 결함 변형 `eval/variants/bug-2`):
  - 정상 상품·정상 필터: 후보 0, 미계획 0.
  - 결함 버전: 심은 버그 3종(수량 하한, 관련 상품 링크, 필터 초기화) 모두 불일치로 잡혔고 재실행에서 재현됐다.
  - 관련 상품은 바뀌는 목록이라 위치로 고정했고, 기대값은 관측 참조(클릭 전 이름)로 비교했다.
  - 결함 버전 탐색에서도 기대값은 요구사항(수량 > 0)이나 관측 참조에서 나왔다. 결함 값으로 고정되지 않았다.
- 다음 할 일: 커밋. Maison 유료 재실측(수량 R3·R4 계획 여부, 관련 상품 판정)은 사용자 승인 뒤. 독립 평가 앱 후보 조사.
