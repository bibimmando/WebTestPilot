# 계획 전 페이지 전처리: QA v2 엔진 (member-01)

> 2026-11-11 · 코드 `qa/` · [멘토링 사전 자료](MENTORING_PREP_member-01_qa-v2.md)의 보충 문서

AI가 검사 계획을 세우기 전에 **코드가 페이지를 어떻게 준비하는지** 정리했습니다.

## 핵심 요약

- **AI 전에 코드가 먼저:** 사이트 지도 수집, 페이지 종류 묶기, 화면 결함 점검은 모두 AI 없이 코드가 합니다.
- **AI 입력 줄이기:** 비슷한 페이지는 한 종류로 묶어 대표 페이지 하나만 탐색합니다. 화면은 HTML이 아니라 접근성 트리로 줍니다.
- **다시 실행할 수 있는 대상만 계획에:** AI가 고른 요소를 코드가 "값·순서에 덜 의존하는 설명"으로 바꿉니다. 하나로 특정되지 않으면 거절합니다.

```
시작 URL (+ 로그인 설정)
  ▼
① 사이트 지도: 같은 사이트 링크를 읽기 전용으로 방문
  ├─ 화면 점검·깨진 링크 ───────────► 보고서 (AI 거치지 않음)
  ▼
② 페이지 종류 묶기: /product/12, /product/35 → /product/:x
  ▼
③ 종류별 AI 탐색: 접근성 트리를 보고 조작 → 검사할 요소를 고정(pin)
  ▼
(다음 단계) 계획 → 실행 → 판정 → 보고서
```

## ① 사이트 지도 수집

- 시작 URL에서 **같은 origin 링크를 GET으로만** 따라갑니다(너비 우선).
- 기본 30페이지까지 방문하고, 같은 종류는 2페이지까지만 봅니다. 못 간 주소도 기록해 "사이트 전체를 봤다"고 주장하지 않습니다.
- **안전장치:** 수집 중에는 쓰기 요청(POST 등)과 다른 사이트로 가는 요청을 막습니다. 로그아웃처럼 앱 설정에서 금지한 주소도 막습니다.
- **로그인:** 앱 설정에 적은 절차로 한 번 로그인해 쿠키를 저장하고, 이후 모든 단계가 그 상태로 시작합니다. 비밀번호는 환경 변수로만 받습니다.
- **SPA:** `#/products/1` 같은 hash 주소도 별도 페이지로 봅니다.
- **깨진 링크:** 404·410·5xx가 나온 링크는 한 번 더 요청해서 또 실패할 때만 확정합니다.

## ② 페이지 종류 묶기

- 페이지 종류마다 AI 탐색 대화를 하나 엽니다. 그래서 묶는 방식이 비용을 좌우합니다.
- 숫자·한글·인코딩이 들어간 경로 조각은 식별자로 보고 `:x`로 바꿉니다.
- 한 위치만 다른 경로가 둘 이상이어도 `:x`로 묶습니다. 첫 조각(`/products`, `/cart`)은 서로 다른 기능이라 묶지 않습니다.
- **한계:** 화면 구조는 비교하지 않고 URL 모양만 봅니다. `/info/faq`와 `/info/returns`처럼 다른 페이지가 묶일 수 있습니다.

## ③ 코드 점검 (AI 없음)

방문한 페이지마다 브라우저가 계산한 값만으로 화면 결함을 찾습니다.

| 점검 | 예 |
|---|---|
| 가려진 버튼 | 버튼 가운데를 누르면 다른 요소가 눌림 |
| 읽을 수 없는 글자 | 글자와 배경의 대비가 2:1 미만 |
| 투명한데 눌리는 요소 | 안 보이는 링크가 클릭을 받음 |
| 채워지지 않은 값 | 화면에 `undefined`, `NaN`, `{{name}}` |
| 모바일 잘림·가로 넘침 | 작은 스크롤 영역에 버튼이 숨음 |
| 이름 없는 조작 요소 | 스크린리더가 읽을 이름이 없는 아이콘 버튼 |

- **오탐 줄이기:** 데스크톱·모바일 두 크기에서 점검합니다. 페이지를 새로 열어 다시 점검했을 때도 나와야 확정합니다.
- 모달 뒤 내용이나 hover 때만 보이는 아이콘처럼 의도된 경우는 뺍니다.
- **화면 안정 대기:** 모든 이동 뒤 네트워크가 잠잠해지고 접근성 트리가 두 번 연속 같을 때까지 기다립니다.

## ④ AI 탐색에 넘기는 것

- **시작 메시지:** 사이트 지도 요약(종류 목록), 이번 대화의 범위, 권한, 요구사항, 일반 규칙 목록을 넣습니다. 점검 결과는 넣지 않습니다.
- **화면:** Playwright 접근성 트리를 줍니다. 요소마다 `ref` 번호가 붙고, AI는 이 번호로 클릭·입력합니다.
- **고정(pin):** ref는 이번 화면에서만 유효합니다. 그래서 코드가 이를 "역할 + 이름"으로 바꾸고, 숫자는 패턴으로 바꿉니다. 요소 **하나만** 가리킬 때만 계획에 쓸 ID를 줍니다.
  - 이름 없는 아이콘 버튼은 근처의 고유한 라벨을 기준으로 삼습니다. 예: "Quantity" 옆 버튼 2개 중 두 번째.
  - 새로 열면 사라지는 요소나 구분이 안 되는 요소는 거절하고, 다른 방법을 알려 줍니다. 첫 요소를 임의로 고르지 않습니다.

## 알려진 한계

- 페이지 종류는 URL 모양으로만 묶습니다. 종류마다 대표 페이지 하나만 탐색합니다.
- iframe·shadow DOM 안은 점검하지 않고 고정할 수도 없습니다.
- 모바일은 화면 폭만 바꾸고, 터치 동작은 보지 않습니다.
- 오래 멈춰 있는 로딩 화면을 준비된 화면으로 오인할 수 있습니다.
- hash 주소 SPA의 "없는 페이지" 화면은 HTTP 404가 없어 깨진 링크로 잡지 못합니다.
- 필터·검색 직후 갱신 전 목록을 읽은 사례가 있습니다(미수정).
