## 1. 목차 (슬라이드 1)

틀린 점:
- 01 "계획 실행에서 실패한 시나리오만 수정하고 성공 항목은 유지"는 사실과 다르다.
  - 바뀐 것은 AI가 계획을 **제출할 때 코드가 검사해서 거부한** 시나리오만 다시 내게 한 것이다.
  - 실행해서 실패한(버그를 찾은) 시나리오를 다시 쓰는 기능이 아니다. 발표 노트에는 맞게 적혀 있는데, 슬라이드 글이 틀렸다.

제안(4개 카드):
1. **입력 검증·UI 결함 탐지 확대**: 실제 제출까지 검사, 화면 점검 7종 추가
2. **보고서 형식 개선**: 결론을 먼저, 근거·재현 절차로 연결
3. **탐색 비용 개선**: 거부된 시나리오만 재제출, 캐시·화면 정보 축소
4. **멘토링과 기말까지 계획**: (지금 내용 유지)

## 2. (새 슬라이드) 입력 검증·UI 결함 탐지 확대

중간발표에서 말한 한계(대본):
- "서버 쪽 검증은 실제 제출이 필요한데 쓰기를 막아 두었다"
- "브라우저 검증 말풍선을 못 읽는다"

한 것:
- **쓰기 허용 + 등록된 초기화로 실제 제출까지 검사한다**(`--allow-writes`, 실행 전·재현 전 데이터 초기화).
  - 중간발표 때는 쓰기를 막아 가입·글쓰기 같은 폼을 끝까지 검사하지 못했다.
- **폼 페이지를 먼저 탐색하고, 메뉴 안에 숨은 로그인·가입 링크도 모은다.**
  - Maison: 폼 시나리오 4개 → 21개, 잘못된 입력 검사 3개 → 14개(11/11, 같은 조건 재실행).
- 값을 넣는 시나리오에 잘못된 입력 검사가 없으면 AI에게 한 번 더 묻는다.
- **화면 점검(코드, AI 없음)을 늘렸다:**
  - 글자 대비
  - 행동 뒤 화면 점검
  - 보이지 않는데 눌리는 요소
  - 깨진 링크
  - 모바일 잘림
  - 채워지지 않은 값(undefined·NaN)
  - 철자

보여 줄 근거(모두 "다시 실행해도 같았음 = 재현됨"):

| 이미지 | 내용 |
|---|---|
| `maison-signup.png` | **입력 검증**: 안내는 "8자 이상"인데 정확히 8자 비밀번호(abcd1234)로 가입하면 오류가 나고 /signup에 머문다(경계값 버그). |
| `agora-title300.png` | **입력 검증**: 제목 300자 제한인데 301자가 들어가고 카운터가 "301/300"으로 표시된다. |
| `maison-header.png` | **UI 결함**: 안내 페이지 제목·breadcrumb가 고정 헤더에 가려진다(화면 판정). |

말하지 말아야 할 것:
- 브라우저 검증 말풍선(유효성 상태) 직접 읽기는 **아직 구현하지 않았다.** 중간발표에서 계획으로 말했으니, 물으면 "남은 과제"라고 답한다.
- 코드 점검 UI 건수(예: Maison 30건)는 "Shop 링크를 로고가 가림" 같은 반복·오탐 의심이 섞여 있어 숫자로 내세우지 않는다.

## 4. 탐색 비용 개선 (슬라이드 3 + 6의 01)

중간발표에서 말한 문제(대본):
- 비용의 89~94%가 탐색·계획이었다(Agora 93%).
- 계획이 거부되면 전체를 다시 썼다.
- 해결 방향으로 "시나리오 단위로 제출하고 화면 정보를 줄이겠다"고 했다.

실제로 한 것(순서대로):

| 날짜 | 무엇을 | 효과(측정) |
|---|---|---|
| 10/28 | **거부된 시나리오만 다시 제출.** 통과한 시나리오는 보관하고, 오류가 난 시나리오와 이유만 돌려준다. | 부분 수락이 실제로 쓰였다(10/30 Maison 6회). 같은 모델 전후 비교로 단독 효과를 잰 적은 없다. |
| 11/03 | **거부 자체를 줄인다.** 저장 실행 분석에서 거부 뒤 재제출이 탐색 비용의 21%였고, 거부 사유의 약 60%가 규칙 형식 오류였다. 그래서 규칙마다 필요한 형식을 계획 안내에 표시했다. | 단독 효과는 미측정 |
| 11/11 | **다시 읽는 앞부분 캐시, 이미 본 화면 영역 접기** | 화면 정보 31% 감소(같은 페이지 행동 뒤 74%), toolshop 탐색 $3.26 → $3.00(-8%), 캐시 쓰기 -16% |
| 11/13 | **예산 예약 계산 수정.** 실제 $0.02~0.05인 호출에 $0.8~1.1을 미리 잡아 두던 것을 고쳤다. | 같은 $6 예산에서 탐색 범위가 늘었다(위시리스트까지 도달, 확신 높은 버그 2건 추가) |

그대로인 것(솔직하게):
- 탐색·계획은 여전히 비용의 약 88%다(Maison 11/14: 탐색 $5.00 / 전체 $5.65).
- 대신 같은 비용으로 더 넓게 본다. Maison 11종을 모두 계획했고 시나리오 54개, 발견 5종이다.

슬라이드 3 제안 문구:
- 제목: **탐색 비용 개선: 다시 쓰는 양과 다시 읽는 양 줄이기**
- 기존: 계획 검증에서 하나라도 틀리면 S1·S2·S3 전체 재작성 / 개선: 거부된 S2만 재제출(지금 그림 그대로)
- 아래 한 줄: 화면 정보 31% 축소·공통 앞부분 캐시 → 탐색 비용 -8%(toolshop). 예산 예약 수정 → 같은 예산으로 Maison 11/11종 탐색.
- "구현 완료, 절감 폭은 확인 예정"은 이렇게 바꾼다: "재제출 단독 효과는 같은 조건 전후 비교 예정, 캐시·접기는 -8% 측정"

- "현재까지 개선: 거부된 시나리오만 재제출 · 캐시·화면 정보 축소(-8%) · 예산 예약 수정"
