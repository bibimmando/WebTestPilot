# WebTestPilot 전처리팀 구현 현황과 역할 분담안

작성일: 2026-10-09. 현재 로컬 코드와 방향성 문서를 읽고 정리한 작업 배분 초안이다. 작업 배정·새 스키마·MCP 연결 방법이 확정됐다는 뜻은 아니다.

## 1. 기준과 핵심 결론

참고 자료:

- [프로젝트 방향성 공유본](WebTestPilot_프로젝트_방향성_공유본.md): 최종 목적·네 검사 범주·재현·모바일·파트 책임.
- [Q1~Q66 최종 입장](WebTestPilot_Q1-Q66_최종_입장.md): 페이지/상태 처리, 같은 브라우저, 초기화와 증거의 기준.
- [세부개발계획 초안](WebTestPilot_세부개발계획_초안.md): 첫 프로토타입의 G0~G3 및 T01~T08 작업.
- 기준 코드: `integration/preprocessor/`.
- 기존 규격: [AI_INPUT_CONTRACT.md](../../integration/docs/AI_INPUT_CONTRACT.md).

같은 프로젝트의 「크롤러 수집 정보 정리」 최근 대화도 확인했다. 처음에는 한 모델이 계획·다음 행동·관찰 해석을 맡는 방향이며, 도구 요청을 검증·실행하고 결과를 반환하는 프로그램 루프가 필요하다. 모델과 실행기의 세부 연결 방식, 첫 실제 결함 사례 선택은 그 대화에서 후속 확인 사항으로 남아 있다.

현재 전처리기는 **URL을 순회하고, 페이지와 행동 전후의 관찰을 저장하고, AI용 요약을 제공하는 기반**까지 구현돼 있다. 전체 방향성으로 이어가려면 **같은 브라우저 연결, 의미 있는 상태·흐름 관리, 재현에 필요한 실행 기록, 이미지와 화면 조건, 로그인·초기화·종료 관리**를 보완해야 한다.

두 명의 분담은 다음처럼 제안한다.

| 담당 | 책임 | 우선 다루는 코드 |
|---|---|---|
| 본인: 실행·탐색·통합 | 브라우저 수명주기, URL/상태 탐색, 흐름 유지, 범위와 종료, AI팀과 같은 탭 연결 | `crawl.py`, `cli.py`, AI 실행기와의 연결부 |
| 다른 팀원: 관찰·요약·증거 | 요소 문맥, 화면 관찰, AI 입력, 전후 증거·diff, 이미지와 증거 인덱스 | `collector.py`, `preprocess.py`, `evidence.py` |

첫 주에는 각 담당의 전체 목록을 완성하려 하지 말고, **같은 탭의 행동 하나가 새 관찰과 증거로 연결되는 작은 버전**을 함께 만든다.

## 2. 현재 구현된 기능

아래의 ‘구현’은 코드가 제공하는 범위다. 이번 정리에서 브라우저 시험이나 유료 모델 호출을 새로 실행하지 않았다. 과거 검증 결과는 root 사본의 [IMPLEMENTATION_STATUS.md](../../archives/docs/preprocessor/IMPLEMENTATION_STATUS.md)에 별도로 있다.

| 영역 | 현재 제공하는 기능 | 중요한 한계 |
|---|---|---|
| 실행 | `single` / `crawl` CLI, Chromium 실행, 같은 실행의 context와 Page 유지 | `crawl()` 내부에서 새 브라우저를 만든다. 외부 MCP와 공동 소유·연결하는 인터페이스는 없음 |
| URL 관리 | 정규화, FIFO 큐, 동일 URL 중복 삽입 억제, 동일 출처 순회 | URL 중복 방지가 메뉴·로그인·입력 결과 등 상태 중복 관리까지 해결하지는 않음 |
| URL 그래프 | 탐색 중 링크·리다이렉트·조작 후 발견 URL과 이동 관계 기록 | 기능 의미를 확정하는 그래프나 완전한 사이트 지도가 아님 |
| 범위·robots | 같은 scheme/host/port, robots 정책, 요청 간격, 문서 리다이렉트 목적지 검사 | 실행 행동별 허용 정책·승인·권한 관리까지 구현된 것은 아님 |
| 문서 분류 | 관찰 MIME 기반 HTML/JSON/XML/파일 역할, 앵커와 경로 해시 처리, 제한된 sitemap 파싱 | sitemap index 재귀·gzip 등은 미지원 |
| 페이지 관찰 | 제목·본문·헤딩, 컨트롤, 폼 연결, label·제약, 선택·표시 상태, bbox·일부 computed style | iframe/shadow DOM 내부 미수집, 원문·요소·본문에 크기/개수 상한 존재 |
| 대상 조회 | 검증한 locator, 요소 key와 안정성 수준, `get_element()` 상세 조회 | 당시 snapshot의 대상이다. 화면이 바뀐 뒤 같은 대상인지 재확인 필요 |
| 오류·이동 관찰 | 콘솔·JS·요청 실패·HTTP 오류, DOM 오류 후보, 실제 URL·redirect·navigation | 관찰된 오류가 곧 사이트 결함은 아님. 시간상 연관과 원인을 구분해야 함 |
| 원본 증거 | 최초 응답, 렌더링 DOM, 관찰된 CSS/JS, PNG, `raw/<URL_ID>/page.json` | 모든 서버 소스·미요청 리소스를 수집하는 기능은 아님. raw에는 민감정보가 남을 수 있음 |
| AI 입력 | `ai_input/1`, 기본 12,288바이트 요약, 기능 후보·네 검사 범주의 관찰 가능 여부·생략 수 | 기능 의미·정상 업무 규칙을 확정하지 않음. UI와 결과 영역의 문맥이 충분하지 않을 수 있음 |
| 행동 증거 | `SnapshotAPI.action()`의 전후 snapshot, diff, 관련 이벤트, 실행/수집 실패 기록 | 행동을 실제 수행하는 실행기가 아님. 입력값·키·선택·준비 조건까지 보존한 재생 기록은 아님 |
| AI 연결점 | `(page, initial_snapshot, evidence)` 콜백, `get_ai_input(snapshot_id)` | 모델·MCP 실행 루프·최종 판정·보고서는 별도 연결 필요 |
| 종료 결과 | 페이지/시간 상한, 대기 URL·정책 차단·콜백 오류·실행 요약 저장, 예외 시 정리 시도 | 사용자 중지용 공용 인터페이스, 행동/API/무변화 반복 상한은 추가 필요 |

현재 콜백 결과는 `passed / failed / not_run`과 snapshot·발견 URL을 처리한다. 상세 검사 계획·판정·보고서 객체를 반환한다고 자동 저장되지는 않는다. 수집 성공은 검사 통과가 아니며 콜백이 없으면 `not_run`이다.

### 네 가지 버그 유형에 제공하는 근거

| 유형 | 이미 수집하는 근거 | 전처리에서 보완할 근거 | AI팀이 수행할 일 |
|---|---|---|---|
| 기능 | 버튼·폼·locator, 일부 상태 변화, 이벤트·diff | 이름 없는 버튼의 주변 문맥, 수량/목록/토스트 등 결과 관찰 | 검사 행동 선택, 실제 실행, 기대 결과와 비교 |
| 입력 검증 | required·pattern·min/max·길이 제약, 오류 후보·표시 상태 | 테스트 입력과 결과 연결, 행동 후 준비 상태, 필요한 검증 메시지 문맥 | 테스트 값 선택, 제출/입력, 제약과 실제 결과 비교 |
| 라우팅 | 링크·실제 URL·리다이렉트·그래프 | 이전 행동/시작 페이지와 도착 관찰의 흐름 연결 | 기대 목적지·화면과 비교 |
| UI | 표시 상태·bbox·스타일·전체 페이지 PNG | 현재 화면 이미지·스크롤·화면 조건, 이미지/요소 참조 | 필요한 정보·조작의 가림/잘림/겹침 판단 |

## 3. 전체 방향성에 맞춰 필요한 전처리 작업

### P0. 첫 프로토타입의 연결에 필요한 작업

| 작업 | 현재 차이 | 전처리팀 산출물 | 담당 제안 |
|---|---|---|---|
| 같은 브라우저·탭 연결 | 전처리가 브라우저를 자체 생성하고 MCP 연결은 없음 | 브라우저 생성/연결/종료 책임 정리, 동일 탭 관찰·행동 확인 | 본인 + AI팀 |
| 대상과 관찰 연결 | 요소 key/locator가 있으나 MCP 대상 참조와의 연결은 미확인 | snapshot과 대상의 연결, 오래된 대상 거부/재관찰, 실행기와 공유 예시 | 다른 팀원 + 본인 + AI팀 |
| 이름 없는 조작 요소 문맥 | text·label이 없는 버튼을 의미적으로 구별하기 어려움 | 제한된 주변 문구·그룹/헤딩·위치·관찰 가능한 아이콘 힌트, 불확실성 표시 | 다른 팀원 |
| 기능 결과 관찰 | 컨트롤 중심 관찰이며 모든 수량/목록 변화가 독립 필드나 diff에 담기는 것은 아님 | 제한된 결과 영역/상태 텍스트와 참조, 전후 비교용 관찰 | 다른 팀원 |
| 행동 후 준비 상태 | 최초 방문의 ready selector는 있으나 행동마다 결과 준비 기준을 연결한 실행 규격은 없음 | 실행기에서 기다린 조건·성공/timeout을 기록하고 새 관찰과 연결 | 본인 + 다른 팀원, AI팀 협업 |
| 사이트·흐름 문맥 | `ai_input/1`은 현재 페이지 중심 | 허용 범위·준비 조건·현재 페이지/이전 행동의 사실과 참조 제공 | 본인, AI팀이 모델 요청 조립 |
| 실제 행동 기록 | 현재 action은 kind·target·전후·오류 중심 | 실제 도구/인자·안전한 입력 또는 참조·시작 조건·순서·증거의 저장 규격 | 본인 + AI팀, 다른 팀원이 증거 저장 연결 |

요소 key와 MCP의 요소 참조는 같다고 가정하지 않는다. 구체적인 연결 방식은 같은 탭 기술 검증 결과로 정한다. Python 전처리기 전체를 새 언어로 옮기는 일을 먼저 잡지 않는다.

`SnapshotAPI.action()`은 행동을 감싸는 증거 기록 도구다. 실제 MCP 행동이 그 기록 경로를 통과하도록 AI팀과 연결해야 한다. 함수의 `kind`에 이름을 넣는 것만으로 실행 권한이나 실제 조작이 검증되지는 않는다.

### P1. 첫 연결 이후 최종 필수 범위를 채우는 작업

| 작업 | 필요한 내용 | 담당 제안 |
|---|---|---|
| 상태와 짧은 흐름 관리 | 같은 URL의 메뉴/모달/로그인/입력 결과를 새 관찰로 처리, 흐름 안에서 상태 유지, 반복 행동/무변화 종료 | 본인, AI팀 협업 |
| 로그인 준비 | 테스트 계정 또는 준비된 로그인 상태 연결, 준비 실패/미검사 영역 표시, 비밀값 보호 | 본인, 테스트팀 협업 |
| 초기화·추가 재현 준비 | 등록된 reset/seed·브라우저 준비 방법 실행, 시작 조건 확인, 최초 증거 보존 | 본인, 테스트팀·AI팀 협업 |
| 화면·이미지 | viewport PNG를 기본으로, 전체 페이지 PNG는 보조, viewport·스크롤·촬영 조건·실패 기록 | 다른 팀원 |
| 모바일 화면 | 합의한 화면 크기 적용, 같은 상태의 화면 조건별 관찰과 참조 | 본인이 환경 적용, 다른 팀원이 수집 |
| 실행 제한·중지 | 범위/허용 행동, 행동 수·API 사용량·무변화 반복 상한 연동, 사용자 중지와 부분 결과 보존 | 본인이 공용 실행 상태, AI팀이 도구/API 경계에 적용 |
| 증거 패키징 | PDF/웹 소비용 상대 참조·필요 증거 인덱스·파일 존재/실패 표시·공유할 증거 구분 | 다른 팀원, AI팀·웹 담당 협업 |
| 품질·평가 지원 | 준비 실패·미지원·잘림·생략 정보, 수집/요약/촬영 시간·바이트 등 실제 측정 | 각 담당 구현, 테스트팀이 평가 |

로그인·준비된 상태 로드와 초기화·재현은 서로 다른 일이다. URL을 넘길 때마다 전부 초기화하지 않는다. 새 context가 서버 데이터와 모든 persist 상태를 복원한다고 가정하지 않는다.

처음부터 완전한 상태 그래프를 만들 필요는 없다. 현재 URL 큐를 유지하고, 진행 중 흐름의 시작 조건·행동 순서·의미 있는 상태 변화와 반복 상한을 먼저 관리한다. 상태 식별 기준과 수치는 실험 후 조정한다.

### 현재 요약에서 특히 보완할 부분

1. Full snapshot에는 bbox와 일부 스타일이 있지만 AI 요약의 `controls`에는 위치/스타일이 포함돼 있지 않다.
2. Full snapshot에는 viewport와 PNG 경로가 있지만 AI 요약에는 화면 조건·이미지 증거 참조가 없다.
3. text/label이 없는 아이콘 버튼에 주변 문맥이나 아이콘 정보를 붙이는 기능은 없다. 특정 사이트의 클래스명만으로 기능을 확정하지 않는다.
4. 컨트롤이 아닌 수량 표시·결과 목록 등은 전체 본문의 일부로만 남을 수 있다. 요약 기본 본문은 1,000자이므로 필요한 결과가 빠질 수 있다.
5. 입력값은 존재/길이만 보존한다. 같은 길이의 숫자 변경처럼 이 정보만으로 구분할 수 없는 경우가 있다. 비민감 테스트 상태를 안전하게 관찰하는 방법과 비밀 입력 참조를 구분해 합의한다.
6. `get_element()`는 상세 조회 기반이지만 모델이 필요할 때 쓰는 제한된 조회 도구로 연결된 것은 아니다. 빠진 정보는 조회로 보완하고 원본 전체를 매번 보내지 않는다.

이 보완의 성공 기준은 요약이 작다는 것만이 아니다. 필요한 행동 대상과 결과를 모델/실행기가 구별할 수 있는지 확인한다. 바이트 감소를 토큰·비용 감소율로 그대로 표현하지 않는다.

## 4. 전처리팀과 다른 파트의 책임 경계

| 항목 | 전처리팀 | AI팀 | 테스트/벤치마크팀 |
|---|---|---|---|
| 기능과 정상 기대 동작 | 관찰 사실·제약·문맥·출처 제공 | 검사 목표와 기대 근거 선택, 불확실성 관리 | 제공 가능한 명세·평가자 정답 준비 |
| 실제 행동 | 브라우저/탐색 환경, 범위·기록 연동 | MCP 연결·모델 도구 루프·행동 검증/실행 | 실행 가능한 사이트/조건 제공 |
| 판정 | 실제 관찰·실행 실패·수집 실패 제공 | 기대/실제 비교, 검토/미완료 구분 | 정답 대조·오탐·미탐 평가 |
| 추가 재현 | 시작 상태 준비와 최초/재현 증거 지원 | 실제 기록한 행동 재생과 결과 해석 | reset/seed·준비 방법 제공, 독립 재현 검증 |
| 최종 JSON·PDF | 안정적인 증거 참조·측정값 공급 | 최종 결과 조립·보고서 생성 | 결과 검증과 평가 |

전처리기는 기능별 정답 목록이나 페이지별 결함 판정기를 전부 구현하는 담당이 아니다. 기존 four-family availability는 관찰 근거의 존재 여부이며 AI 검사 생략 스위치가 아니다. 기본 실행은 범위·한도 안에서 발견한 페이지/기능 상태를 점진적으로 검사하고 선택적 AI 호출은 후속 비교 실험으로 다룬다.

정답 유출 방지는 테스트/평가팀과 별도로 합의한다. 예를 들어 테스트 사이트에 결함 라벨·정답 endpoint·메타데이터가 있다면, 판단 모델에게 주는 요약과 도구 결과에서 이를 제외한다. 실제 앱이 설정을 읽는 요청을 차단해 결함 동작 자체를 없애는 방식은 사용하지 않는다. 평가용 원본 보관과 모델/공유 출력은 별도 경로로 다룬다.

## 5. 다른 팀원에게 바로 맡길 작업 묶음

**작업명: 페이지 관찰과 AI 입력·증거 보완**

### 첫 번째 작업: 조작 요소와 결과를 구별할 수 있는 요약

- 대상 코드: `collector.py`, `preprocess.py`.
- 입력: 기존 live Page와 snapshot. 별도 크롤러나 AI 호출은 만들지 않는다.
- 작업: 이름 없는 버튼의 주변 문맥, 제한된 결과 상태 텍스트/참조, 필요한 위치·화면 정보 제공.
- 유지할 것: 요소 key·locator, 입력값 보호, 요약 크기 상한, 잘림/생략/불확실성 정보.
- 완료 기준: 로컬 fixture에서 두 아이콘 버튼을 관찰 정보로 구별할 수 있고, 행동 전후의 숫자/목록 변화를 구조화된 관찰이나 상세 조회로 확인할 수 있다. 대상이나 결과가 미수집됐으면 그 한계가 명시된다.
- 검증: 모델 없이 기대한 관찰 필드가 존재하고, 참조가 실제 요소/증거에 연결되며 민감 입력이 노출되지 않는지 확인한다.

### 두 번째 작업: 현재 화면 증거와 인덱스

- 대상 코드: `collector.py`, `evidence.py`, 필요한 요약 필드.
- 작업: viewport 이미지, 필요 시 full-page 이미지, viewport/스크롤·촬영 조건과 증거 참조 연결.
- 완료 기준: 행동 전후 사진과 JSON이 같은 snapshot/action에 연결되고, 촬영 실패는 별도 오류로 남는다. 모바일 화면 크기의 관찰도 조건을 구별할 수 있다.
- 주의: full-page 촬영은 이미 있으므로 새로 만드는 대신 기존 저장 경로와 인덱스를 확장한다. 모든 PNG를 기본 모델 입력에 첨부하지 않는다.

### 세 번째 작업: 실행기에서 오는 기록의 증거 연결

- 대상 코드: `evidence.py`와 공용 규격 문서.
- 선행: 본인·AI팀이 실제 행동 기록의 최소 필드를 합의.
- 작업: 실제 도구 호출/안전한 인자 참조·흐름/검사 식별 정보·전후 snapshot·실패를 연결한다.
- 완료 기준: 같은 검사에서 최초 실행과 추가 재현을 별도 기록으로 찾을 수 있다. 실행기 실패와 수집 실패가 사이트 결함으로 변환되지 않는다.

첫 번째 작업을 기본 배정으로 전달하고, 두 번째·세 번째는 통합 결과와 가용 시간에 맞춰 이어간다. 새로운 스키마 이름·상세 필드와 파일은 작업 시작 전에 AI 소비자와 함께 최소한만 정한다.

## 6. 본인이 병행할 작업

1. 기준 경로와 실행 안내 정리. root와 팀 디렉토리의 주요 Python 파일 7개는 이번 확인에서 동일했다. 공식 경로 하나를 발전시키고 다른 사본은 새 기능을 따로 개발하지 않는다.
2. AI팀과 같은 브라우저·탭의 생성/접속/종료 책임을 합의하고 무과금 기술 검증을 수행한다.
3. 기존 URL 큐는 유지하고, 연결 흐름 안에서 상태를 보존하는 실행 규칙과 반복 상한을 붙인다.
4. 사이트 문맥·시작 조건·실제 행동/결과의 연결을 AI팀과 정하고, 필요한 전처리 사실을 제공한다.
5. 테스트팀이 준비한 로그인·초기 상태·복원 프로필을 연결한다. 단순 첫 사례에는 필요한 준비만 적용한다.
6. 공용 한도·중지·부분 결과 상태를 연결하고 각 파트의 검사/수집/보고 상태를 구분한다.

PM 업무를 병행한다면 기능 보완까지 모두 직접 맡지 않고, 팀원이 관찰·요약·증거를 독립적으로 시연할 수 있는 완료 기준을 제공하는 편이 좋다.

## 7. 첫 연결의 검수 순서

| 순서 | 담당 | 보여줄 결과 |
|---|---|---|
| 1 | 각 파트, 본인 조율 | 기준 코드·실행 명령·기존 입력 예시가 일치 |
| 2 | 본인 + AI팀 | 모델 없이 MCP 행동 하나와 같은 탭의 전후 증거가 연결 |
| 3 | 다른 팀원 | 그 행동의 대상·결과·이미지/참조를 관찰에서 확인 |
| 4 | AI팀 + 전처리팀 | 모델이 행동을 선택하고 새 관찰을 받아 후속 판단 |
| 5 | 테스트팀 + 각 파트 | 사례의 정상/결함 독립 실행, 추가 1회 재현, 근거·증거 연결 JSON |

세부계획의 F3 수량 증가 무반응은 첫 실제 사례 후보다. 최종 선택과 배포 상태는 테스트팀과 확인해야 한다. 대상 `+` 버튼 이름이나 알려진 결함을 하드코딩해 검사 모델에 정답을 주는 방식으로 완료하지 않는다. 고정 행동으로 연결을 확인하는 시험과 AI가 검사 행동을 선택하는 시험은 구분한다.

두 담당이 동시에 `evidence.py`를 크게 수정하지 않도록 관찰·증거 구현은 팀원, 실행 연결은 본인이 주도한다. 연결 API 변경은 작은 예시와 완료 기준을 먼저 합의한다.

## 8. 우선순위를 낮출 작업

- 사이트 전체 URL 그래프를 먼저 완성하는 선행 크롤링.
- 모든 CSS/JS를 AI에게 보내거나 프런트엔드 소스로 정상 규칙을 역추론하는 기능.
- 완전한 상태 그래프, 무제한 사용자 흐름, 자동 중단 지점 복구.
- CAPTCHA/접근 제한 우회, 모든 브라우저·실기기 대응.
- 페이지 중요도에 따라 AI 호출을 생략하는 최적화를 첫 연결보다 먼저 적용하는 작업.
- 전처리팀이 판정·PDF·웹 UI·배포까지 자동으로 떠맡는 배분.

iframe/shadow DOM/popup은 현재 관찰 한계를 명시한다. 선택한 첫 사례나 벤치마크가 실제로 요구할 때 필요한 지원을 추가한다. 로그인과 모바일 화면 검사는 최종 필수 범위이므로 단순히 미지원 목록에 남겨 둔 채 완료하지 않는다.
